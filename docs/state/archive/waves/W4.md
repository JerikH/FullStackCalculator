## Build first, verify after (U36) and the 10-minute limit (U22)

**U36, binding on both workers.** Do not edit a line and then run a package of hundreds of tests, over and over. Build the whole member first — every file, its tests and checks written, the records drafted — running while you build at most the cheapest check that unblocks the next edit (a compile, `bash -n`, a typecheck, one test file, `actionlint` on the one file). When the build is complete, run the checks relevant to what changed, once each, in the order of the run's plan. A failure re-runs only the failing piece, then the relevant pieces once more. Whole-suite, coverage, fuzz, benchmark and image pieces run when the task names them as its proof or when something more important requires it (a gate, a shared piece that failed, a mutation proof) — never as a per-edit loop. Mutation checks run after the build, one at a time, restored before the next. Waiting for a lease or a long command never blocks the build: do other work.

**U22, binding on both workers.** No local command — test suite, coverage run, benchmark, image build, scan, Playwright or browser check, tier script — may take 10 minutes of wall-clock time or more. Wrap any command that could run long in `timeout 600`; split what cannot fit into pieces that each fit, or leave it to CI and record it in `closure.md` with the reason; take leases without `--wait` first and keep working while one is held (`--wait` only with `--timeout 600`, and only when nothing else can advance); never sit waiting on a running command; a timeout is a finding to fix by narrowing the scope, never a reason to raise the limit or weaken the check. The `heavy` lease serializes coverage, fuzz, bench and image pieces between the two workers. Recipe: `docs/state/context/test-environment.md`, «10-minute limit on every local command».
