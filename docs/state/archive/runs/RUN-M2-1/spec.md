### 2. Edge (U21) — `deploy/nginx/default.conf.template`

- `limit_conn_zone $binary_remote_addr zone=apiconn:10m;` next to the `limit_req_zone`; in `location /api/` of the outer server `limit_conn apiconn 20; limit_conn_status 429;` (the location's existing `error_page 429 = @rate_limited` answers it). The inner hop on loopback is not limited (a held request counts once, in the outer hop).
- `client_max_body_size 16k;` in `location = /healthz` and `location = /readyz`; the existing `error_page 413 = @payload_too_large` answers it. A probe body sent with a `Content-Length` of 16 KiB or less is held in nginx's memory buffer (`client_body_buffer_size` default 16k on 64-bit); a chunked body that fills the buffer may spill to `/tmp`, bounded by the 16 KiB limit and the 64 MiB tmpfs cap. `limit_conn_log_level warn` is set on the limit so a refused connection is not an `error` line.
- Static files and the probes stay without a connection limit (U21).
- The web tmpfs cap is the compose file's (section 3).
- Proof: `edge-smoke.sh` (a copy in this run's evidence, Node pin 24.22.1 for the stub, repository root found from the copy's location) gains (a) 20 held connections (raw sockets that send the headers of a POST with a `Content-Length` and no body) and a 21st request on `/api/` answered with the `RATE_LIMITED` 429 problem valid against the contract, while `/`, `/nginx-health` and `/healthz` still answer, and a request after the sockets close answers normally. The held sockets are asserted still pending (no response byte) before the 21st request, they are held for less than `client_body_timeout` (10 s), and the section runs after the bucket of `limit_req` has refilled (≥ 3 s after any burst), so the 429 can only come from the connection limit and the `limit_conn` mutation is caught; (b) a probe `GET` with a 16 KiB + 1 body refused with the `PAYLOAD_TOO_LARGE` 413 problem, and a 16 KiB body accepted (answered by the stub like any probe). `mutations.sh` (copy) gains the two new mutations (delete the `limit_conn` line; raise the probe limit to `1m`) and keeps the rate-limit mutation (M5-style: `limit_req` on the probe) and the probe-body-limit mutation ones; the other existing mutations are not re-run: the change is additive (the diff shows it).
