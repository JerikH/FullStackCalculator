### Findings of W1 — wave integration (2026-10-22)
- (a) **API, UI** [topic: api-contract] [type: rule] — Rule confirmed at integration: the problem code list has two scopes. The contract's `ProblemCode` enum (13 codes) and the client's `PROBLEM_CODES` (`frontend/src/shared/api/problem.ts`, checked against the generated enum in both directions at compile time) are equal; `httpx.Codes()` (`backend/internal/platform/httpx/problem.go`) is the 11 codes the Go service emits — the enum minus `RATE_LIMITED` and `SERVICE_UNAVAILABLE`, which RF-API-05 marks edge-only (emitted by the edge, RF-OPS-04). The invariant is `Codes()` ⊆ enum = `PROBLEM_CODES` (RF-API-09); an expectation of equality between the service list and the client list is wrong, and no member diverged from the contract. Today `TestCodesIsSortedAndComplete` pins the 11; the subset assertion against the embedded contract is API-ROUTES-01's contract test.
- (b) **API, OBS** [topic: api-contract, observability] [type: debt] [target: API-ROUTES-01, OBS-METRICS-01] — `httpx.WriteJSON(w, r, status, v)` takes the request, unlike the three-argument form the handlers were first sketched with: accepted at integration because RF-API-05 requires `instance` and `requestId` on every service problem, including the encoding fallback (a programming error turned into an `INTERNAL_ERROR` problem), and only the request carries them. API-ROUTES-01 writes every JSON response through this signature (calculate, list operations, the healthz/readyz probes and the draining 503); OBS-METRICS-01 reads the recorded status from `httpx.Info(ctx).StatusOrOK()` («Findings of API-HTTPX-01» (e)).
- (c) **CALC, DOC** [topic: performance-scale] [type: note] — ADR 0002 states that the cost of one operation is bounded by the precision cap, so no per-request timeout is needed, measured by the six `BenchmarkCalculate` cases (< 1,000,000 ns/op). Re-measured at integration alone under the `heavy` lease (`go test ./internal/calc -run '^$' -bench . -benchmem -count=3`): 1.4–620 µs/op; `power_fractional` 380–620 µs on this machine against 302 µs in the worker run (820 µs in a first run that overlapped a frontend install, discarded), so its margin to the bound is under 2×. «Findings of CALC-OPS-01» (c) measured worst-case fractional powers at 13.2 ms; the owner decision on that backlog item (document the bound, add a worst-case benchmark case, or bound the working precision) also decides whether ADR 0002 needs a superseding ADR.
