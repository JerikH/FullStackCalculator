### Findings of UI-CLIENT-01 — typed, never-throwing API client (2026-10-22)
- (a) **UI** [topic: api-contract, reliability-errors] [type: rule] — Rule as built: `createCalculatorApi({ baseUrl, timeoutMs = 8000, fetch? })` posts `{ operands: [...operands] }` to `/api/v1/operations/{operation}` through openapi-fetch with a per-request `fetch` (late-bound `globalThis.fetch` by default) and always an `AbortSignal.timeout`, combined with the caller's signal through `AbortSignal.any`. It never rejects: a response that settles after the combined signal fired → `timeout`/`aborted` (stale bodies never come back as `ok`); 2xx with a `CalculationResult` for the requested operation whose operands and result are contract Decimals (pattern, ≤ 128 characters) → `ok` with an object rebuilt from the four contract fields only; any other 2xx (wrong shape, other operation, non-Decimal, empty, 204) → `unexpected(status)`; non-2xx whose body passes `isProblem` and whose `status` equals the HTTP status → `problem(status, code, title, detail, requestId)`; any other non-2xx → `unexpected(status)`; a thrown error while the combined signal is aborted → `timeout` when the timeout fired first, else `aborted`; an unparsable 2xx body (an object named `SyntaxError`, checked without `instanceof`) → `unexpected(status)`; anything else → `network`. `isProblem` requires string `type`, `title`, `detail`, `requestId`, an integer `status` 400–599, a `code` in `PROBLEM_CODES`, and checks `instance` and `errors` when present. `PROBLEM_CODES` is checked against the contract enum in both directions at compile time. `resolveBaseUrl(configured, origin)` returns the origin for an unset or empty value.
- (b) **UI** [topic: api-contract, ui-accessibility] [type: debt] [resolved: UI-MODEL-01] — The contract types `requestId` as a string without a minimum length, so a problem with `requestId: ""` reaches the model as a problem with an empty reference. RF-UI-08 shows `Ref: <requestId>` «when available»: the model's error copy treats an empty `requestId` as unavailable (no bare `Ref: `) and tests it. `title`, `detail` and `requestId` are copied verbatim, without a length cap or control-character filtering (a `title` with U+202E passes the guard): the UI never shows `title`/`detail` (RF-UI-08) and renders `requestId` only as a React text node, never as HTML.
- (c) **UI** [topic: api-contract] [type: debt] [target: UI-SCREEN-01] — The client is created once by the real `main.tsx`: `createCalculatorApi({ baseUrl: resolveBaseUrl(import.meta.env.VITE_API_BASE_URL, window.location.origin) })`, provided through `CalculatorApiProvider` around the app (RF-UI-09 «created once and injected through React context»); `useCalculatorApi` throws outside the provider.
- (d) **UI** [topic: security-privacy, api-contract] [type: note] — Security and edge-case review (step 10, independent subagent): no P0–P2. Applied: results rebuilt from the contract fields with Decimal checks (a `__proto__` own key in a 2xx body no longer reaches the caller) and stale bodies reported as aborted/timeout. Recorded, not changed: `resolveBaseUrl` trusts the build-time `VITE_API_BASE_URL` as given (a query or fragment in it would produce a wrong URL; it is operator configuration, and the same-origin default needs none); the production build emits source maps with `sourcesContent` (`build.sourcemap: true`; no secrets, absolute paths or environment values in them — whether the edge serves `.map` files is the edge configuration's choice); `operation` path values are percent-encoded by openapi-fetch; requests carry no credentials beyond same-origin defaults; `pnpm audit --prod` reported no known vulnerabilities (2026-10-22).

### Findings of UI-MODEL-01 — pure calculator model (2026-10-22)
- (a) **UI** [topic: state-machine, numeric-precision] [type: rule] — Rule as built (`frontend/src/features/calculator/model/`, no React, DOM, IO, timers, randomness or numeric conversion; `boundaries.test.ts` scans the eight production sources): `OPERATIONS` holds the contract symbols (`+ − × ÷ ^ √ %`) and arities, and a compile-time alias fails when a contract operation is neither binary nor unary. `KEYPAD` is the single table of 23 frozen keys (row-major, `=` spanning rows 5–6, RF-UI-01 names and variants, RF-UI-02 bindings as `KeyboardEvent.key` values); `commandForKey` is a `Map` built from it (case-sensitive; Space, `R`, `N`, `__proto__` unbound); `actionForCommand` is exhaustive. Entry editing is string-only (34-digit cap counting `0`–`9`; scientific entries unchanged by a digit or a point; ± never grows an entry past 128 characters). `calculatorReducer` guards in order: a non-Decimal recall → same state; a completion whose `request` is not the very object in `state.request` → same state (so a late completion of a request dropped by AC is ignored even when the new request reuses its number); busy → only AC and completions; error → digit, point and recall reset then apply, C/AC reset, clear history stays in error. `entryMode` is `typing`, `fresh` (result or recall) or `operand` (the stored left operand); a binary operator replaces the pending operator only in `operand`, otherwise it issues the pending operation and chains. Any action that changes no field returns the same object; produced states, requests, operands and histories are frozen. A success with an invalid or duplicate `historyId` applies the result without a history entry; a success whose result is not a contract Decimal is applied as a failure (`Something went wrong`). `selectDisplay`/`formatEntry`/`historyExpression` format for presentation only (U+2212, linear `,` grouping of the integer part, scientific ungrouped, `≈` kept out of `value`, size xl ≤ 10 / lg ≤ 16 / md). `toCalculatorError` maps all 13 codes and the network/timeout/unexpected kinds to the RF-UI-08 copy and carries `requestId` only when it matches `^[A-Za-z0-9._-]{1,128}$`. `decodeHistory` (≤ 65,536 code units, own properties only, any malformed entry or duplicate ID → `[]`, first 20 kept, frozen) and `encodeHistory` (drops what decode would reject, then caps at 20; deterministic) form the versioned codec for `calculator.history.v1`.
- (b) **UI** [topic: state-machine, reliability-errors] [type: debt] [target: UI-HOOKS-01] — Contract the effects layer must follow: dispatch `calculationSucceeded`/`calculationFailed` with the exact `state.request` object the effect captured (never a rebuilt descriptor or a number; request IDs restart at 1 after AC and error recovery, so deduplicating by `request.id` is wrong); dispatch nothing for `aborted`; build the failure with `toCalculatorError`; give each success a unique `historyId` of at most 128 characters (`crypto.randomUUID()`); create the state with `createInitialState(decodeHistory(raw))` and persist `encodeHistory(state.history)` under `HISTORY_STORAGE_KEY` through `safeStorage`; map key events with `commandForKey(event.key)` + `actionForCommand` (the guards for modifiers, editable targets, IME and button/summary/radio Enter/Space stay in the hook). The effect-instance `active` flag stays as defence in depth.
- (c) **UI** [topic: ui-accessibility, security-privacy] [type: debt] [target: UI-SCREEN-01] — Rendering contract of the model's outputs: `DisplayModel.value` and `expression` are text (the `≈` marker, its title and the accessible explanation `Rounded to 34 significant digits` are added by the screen from `inexact`); the error shows `error.message` and `Ref: <requestId>` only when `requestId` is present, as React text; history items read `historyExpression(entry)` with the accessible name `Use result ${formatEntry(entry.result)}` and recall `entry.result` (raw); key placement comes from `KEYPAD` `row`/`column`/`rowSpan` through CSS classes (no inline styles). History IDs are only length-checked (1–128 characters; bidi and control characters pass the codec): use them only as React keys, never as visible text or in `id`/`aria-*` attributes.
- (d) **UI** [topic: state-machine] [type: note] — Owner answer of 2026-10-22 (asked in RUN-M1-5, to be recorded as the next owner decision): a binary operator pressed after a unary result or a history recall issues the pending operation and chains (`9 + 16 √ × 2 =` → add `["9","4"]`, then multiply `["13","2"]`; `9 + [recall 36] × 2 =` likewise); only a value that is itself the stored left operand — right after a binary operator or a chained result — has its pending operator replaced (`2 + × 3 =` → 6). RF-UI-04's literal «one pressed while fresh replaces the pending operator» read the other way and was reworded (closure).
- (e) **UI** [topic: testing-environment, agent-process] [type: trap] — `Array.prototype.every` skips holes, so `new Array(2).every(isDecimal)` is `true`: validate `Array.from(value)` (the encoder had this gap until the independent review). Codex's read-only review sandbox cannot start Vitest (`EROFS` writing `node_modules/.vite-temp`); it can run `tsc` and in-memory Node probes, so the controller runs the suites. `--coverage.reportsDirectory=$WF_SCRATCH/…` needs `eval "$(.workflow/bin/wf env --export)"` in the same shell (an empty variable resolves to `/coverage` and fails with `EACCES`).
- (f) **UI** [topic: agent-process] [type: note] — Cycle notes: spec review (Claude subagent) 2 P1, 3 P2, 9 P3 — the reused-ID stale completion the spec had left to the hooks contradicted RF-UI-04 and UC-UI-01 E5 (now an identity guard), and the operator-after-unary/recall case went to the owner; plan review (Codex) 5 P2, 1 P3, all applied (mutation table, `press` with `KeyboardEvent.key` values, freeze assertions, exact coverage command, D13 checks); implementation: Codex wrote keypad/entry/reducer (443 tests), a Sonnet subagent wrote selectors/messages/history/operations/boundaries tests (381 tests); second independent reader (Codex) 1 P2 (sparse operands in the encoder), 1 P3 (quoted import names evading the scanner); security review (Claude subagent, 2,000-run fuzz, crafted storage) 0 P0–P2, 3 P3 (quadratic grouping regex unreachable under the 128-character bound, now linear; defence in depth for non-Decimal results and inherited problem codes; history-ID characters → (c)).
