### Findings of API-CONTRACT-01 — OpenAPI contract and Redocly configuration (2026-10-22)
- (a) **API** [topic: api-contract, testing-environment] [type: debt] [target: API-ROUTES-01] — Response validation against the document looks operations up by the request's method, so a wrong-method request (no operation for that method) cannot be validated as a response of the contract (`POST Path '/healthz' not found`, libopenapi-validator v0.16.1). The contract tests validate every 405 body against `#/components/schemas/Problem` and assert the `Allow` header instead, for the operation endpoints and for `/healthz`, `/readyz` and `/api/v1/openapi.yaml`.
- (b) **UI, OPS** [topic: api-contract] [type: debt] [target: UI-CLIENT-01, OPS-EDGE-01] — `Problem.required` in the contract is `type, title, status, detail, code, requestId` (RF-API-05/07: every problem carries them; `instance` may be omitted only by the edge). Consequences: the generated `Problem` type has `detail` and `requestId` as required strings, so the client's `isProblem` guard checks both are strings and the problem result copies them without `!== undefined` conditions (strict lint flags unnecessary conditions; RF-UI-09's `detail?`/`requestId?` stay optional in the client's own result type); the edge's 429/503/413 problems built in nginx carry `detail` and the validated `requestId` and validate against the schema. The service side is enforced by the contract tests of API-ROUTES-01, which validate every problem response against the document.
- (c) **OPS** [topic: testing-environment, ci-supply-chain] [type: trap] — `pnpm dlx @redocly/cli@<version> lint` fails with `ERR_PNPM_DLX_MULTIPLE_BINS` (the package ships `redocly` and `openapi` binaries). Working form: `pnpm --package=@redocly/cli@<version> dlx redocly lint backend/api/openapi.yaml`. Measured: about 2 s per lint with Redocly CLI 2.69.0.
- (d) **API** [topic: api-contract] [type: rule] — Rule as built: each operation of `backend/api/openapi.yaml` declares the statuses the requirements assign to it: `listOperations` 200/405/429/500/503; `calculate` 200/400/404/405/413/415/422/429/500/503; `getOpenAPIDocument` 200/405/429/500/503; `getLiveness` 200/405/500; `getReadiness` 200/405/500/503 (Health). 405 on every GET-only path (RF-API-06), 500 everywhere (RF-API-11), edge 429/503 only on `/api/*` (RF-OPS-04; probes pass through).
