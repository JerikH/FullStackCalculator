### Findings of UI-MODEL-01 — pure calculator model (2026-10-22)
- (a) **UI** [topic: state-machine, numeric-precision] [type: rule] — Rule as built (`frontend/src/features/calculator/model/`, no React, DOM, IO, timers, randomness or numeric conversion; `boundaries.test.ts` scans the eight production sources): `OPERATIONS` holds the contract symbols (`+ − × ÷ ^ √ %`) and arities, and a compile-time alias fails when a contract operation is neither binary nor unary. `KEYPAD` is the single table of 23 frozen keys (row-major, `=` spanning rows 5–6, RF-UI-01 names and variants, RF-UI-02 bindings as `KeyboardEvent.key` values); `commandForKey` is a `Map` built from it (case-sensitive; Space, `R`, `N`, `__proto__` unbound); `actionForCommand` is exhaustive. Entry editing is string-only (34-digit cap counting `0`–`9`; scientific entries unchanged by a digit or a point; ± never grows an entry past 128 characters). `calculatorReducer` guards in order: a non-Decimal recall → same state; a completion whose `request` is not the very object in `state.request` → same state (so a late completion of a request dropped by AC is ignored even when the new request reuses its number); busy → only AC and completions; error → digit, point and recall reset then apply, C/AC reset, clear history stays in error. `entryMode` is `typing`, `fresh` (result or recall) or `operand` (the stored left operand); a binary operator replaces the pending operator only in `operand`, otherwise it issues the pending operation and chains. Any action that changes no field returns the same object; produced states, requests, operands and histories are frozen. A success with an invalid or duplicate `historyId` applies the result without a history entry; a success whose result is not a contract Decimal is applied as a failure (`Something went wrong`). `selectDisplay`/`formatEntry`/`historyExpression` format for presentation only (U+2212, linear `,` grouping of the integer part, scientific ungrouped, `≈` kept out of `value`, size xl ≤ 10 / lg ≤ 16 / md). `toCalculatorError` maps all 13 codes and the network/timeout/unexpected kinds to the RF-UI-08 copy and carries `requestId` only when it matches `^[A-Za-z0-9._-]{1,128}$`. `decodeHistory` (≤ 65,536 code units, own properties only, any malformed entry or duplicate ID → `[]`, first 20 kept, frozen) and `encodeHistory` (drops what decode would reject, then caps at 20; deterministic) form the versioned codec for `calculator.history.v1`.
- (b) **UI** [topic: state-machine, reliability-errors] [type: debt] [target: UI-HOOKS-01] — Contract the effects layer must follow: dispatch `calculationSucceeded`/`calculationFailed` with the exact `state.request` object the effect captured (never a rebuilt descriptor or a number; request IDs restart at 1 after AC and error recovery, so deduplicating by `request.id` is wrong); dispatch nothing for `aborted`; build the failure with `toCalculatorError`; give each success a unique `historyId` of at most 128 characters (`crypto.randomUUID()`); create the state with `createInitialState(decodeHistory(raw))` and persist `encodeHistory(state.history)` under `HISTORY_STORAGE_KEY` through `safeStorage`; map key events with `commandForKey(event.key)` + `actionForCommand` (the guards for modifiers, editable targets, IME and button/summary/radio Enter/Space stay in the hook). The effect-instance `active` flag stays as defence in depth.
- (c) **UI** [topic: ui-accessibility, security-privacy] [type: debt] [target: UI-SCREEN-01] — Rendering contract of the model's outputs: `DisplayModel.value` and `expression` are text (the `≈` marker, its title and the accessible explanation `Rounded to 34 significant digits` are added by the screen from `inexact`); the error shows `error.message` and `Ref: <requestId>` only when `requestId` is present, as React text; history items read `historyExpression(entry)` with the accessible name `Use result ${formatEntry(entry.result)}` and recall `entry.result` (raw); key placement comes from `KEYPAD` `row`/`column`/`rowSpan` through CSS classes (no inline styles). History IDs are only length-checked (1–128 characters; bidi and control characters pass the codec): use them only as React keys, never as visible text or in `id`/`aria-*` attributes.
- (d) **UI** [topic: state-machine] [type: note] — Owner answer of 2026-10-22 (asked in RUN-M1-5, to be recorded as the next owner decision): a binary operator pressed after a unary result or a history recall issues the pending operation and chains (`9 + 16 √ × 2 =` → add `["9","4"]`, then multiply `["13","2"]`; `9 + [recall 36] × 2 =` likewise); only a value that is itself the stored left operand — right after a binary operator or a chained result — has its pending operator replaced (`2 + × 3 =` → 6). RF-UI-04's literal «one pressed while fresh replaces the pending operator» read the other way and was reworded (closure).
