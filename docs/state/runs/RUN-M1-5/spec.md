## Design decisions

D1 — **Operation metadata in one table.** `OPERATIONS` maps every `OperationName` to `{ symbol, arity }` with the contract symbols, `satisfies Record<OperationName, …>`; `BinaryOperation`/`UnaryOperation` are `Extract`s of `OperationName`, with a compile-time check that they partition it (a new contract operation fails the type check until it is classified). Display, history text, the codec's arity check and the keypad all read this table. The power key's label stays `xʸ` (RF-UI-01); its expression symbol is the catalog's `^` (`2 ^ 10 = 1024`).

D2 — **Unchanged → same object.** Every action that changes no field returns the previous state object (`toBe`), not only the ignored actions of the guards: `=` with no pending operator, ⌫ or a digit beyond the cap, a second decimal point, ± on `"0"`, operator replacement with the same operator, C or AC on a state already in that shape, clear history on an empty history. Implemented once: the reducer compares the candidate with the input field by field (`Object.is`) before returning. This keeps React bail-outs and the identity tests meaningful.

D3 — **Guard order.** (1) a completion (`calculationSucceeded`/`calculationFailed`) whose `requestId` differs from `state.request?.id`, or with `state.request === null`, returns the state; (2) `status === 'busy'` and the action is not AC or a completion → state; (3) `status === 'error'`: digit, decimal point and recall reset (initial state, history kept, `nextRequestId` 1) and then apply in the reset state; C and AC reset; clear history empties history and stays in error; everything else → state; (4) the transition table. Invariant (tested over generated sequences): `request !== null` ⇔ `status === 'busy'`; `error !== null` ⇔ `status === 'error'`.

D4 — **Transitions exactly as RF-UI-03/RF-UI-04.** Digit when fresh: `entry = d`, typing, `inexact = false`. Decimal when fresh: `"0."`, typing, `inexact = false`. ± toggles the leading `-` (not on `"0"`), mode and `inexact` unchanged. ⌫ when fresh: no-op. C: `entry "0"`, typing, `inexact false`, `error null`, `status idle`, operator and accumulator kept. AC: initial state, history kept, `nextRequestId` 1. Binary with pending operator and typing → issue `{pendingOperator, [accumulator, toOperand(entry)], chain(op)}`; with pending and fresh → replace the operator; with none → `accumulator = toOperand(entry)`, `pendingOperator = op`, fresh (`inexact` unchanged: the value on screen is still the same). Unary → issue `{op, [toOperand(entry)], replaceEntry}` (pending operator and accumulator kept). `=` with `pendingOperator !== null && accumulator !== null` → issue `{pendingOperator, [accumulator, toOperand(entry)], complete}`; otherwise no-op (no repeat-last-operation). Recall → `entry = value`, fresh, `inexact false`, operator kept. Success: by the captured request's continuation — complete: entry = result, accumulator and operator null, fresh; chain(op): entry = accumulator = result, operator `op`, fresh; replaceEntry: entry = result, fresh; all: `inexact = payload.inexact`, idle, `request null`, history entry prepended, capped at 20. Failure: error status, `error = payload`, request, accumulator and operator null, entry `"0"`, fresh, history unchanged. Issue = `request {id: nextRequestId, operation, operands (fresh frozen array), continuation}`, `nextRequestId + 1`, busy, `error null`.

D5 — **History entry content.** Operation and operands from the captured request (what was asked), result and inexact from the payload; `id` = the action's `historyId`. The reducer does not compare `payload.operation` with the request (the client already guarantees it). Equal calculations stay separate entries.

D6 — **Recall value is checked.** `historyRecalled` with a value that is not a contract Decimal (≤ 128 characters) returns the state unchanged in every status. Values come from the codec or the API, both already validated; the check keeps the entry invariant (every entry `toOperand`s to a contract Decimal) independent of the caller.

D7 — **Typing-mode entries are plain.** Scientific values only enter as results or recalls, always fresh; a digit or decimal point replaces a fresh entry, ⌫ ignores it, ± only edits the sign. So `appendDigit`/`appendDecimalPoint`/`backspace` never see an exponent from the reducer; the exported functions still behave as specified on their own table. The digit cap counts characters `0`–`9` (the leading zero of `0.` included), not significant digits.

D8 — **Formatting is presentation only.** `formatEntry`: a leading `-` becomes U+2212; a value containing `e`/`E` is returned ungrouped (exponent sign stays ASCII); otherwise the integer part is grouped with `,` by a string regex, the fraction (with its trailing zeros) and an unfinished `.` kept. `selectDisplay`: `value = formatEntry(entry)`; `expression = formatEntry(accumulator) + " " + symbol` when both accumulator and pending operator are non-null, else `""`; `size` by `value.length` (U+2212 and commas counted, the `≈` marker excluded): ≤ 10 `xl`, ≤ 16 `lg`, else `md`; `inexact`, `busy` (`status === 'busy'`), `error` copied. `historyExpression`: binary `a sym b = r`, sqrt `√a = r`, percentage `a% = r`, with `≈` instead of `=` when inexact, every number through `formatEntry`. The UI builds `Use result <formatEntry(result)>`.

D9 — **Error copy.** `PROBLEM_MESSAGES satisfies Record<ProblemCode, string>` with an explicit entry for all 13 codes (RF-UI-08 copy; `NOT_FOUND`, `UNKNOWN_OPERATION`, `METHOD_NOT_ALLOWED`, `PAYLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`, `INTERNAL_ERROR` → `Something went wrong`). `toCalculatorError(error: Exclude<ApiError, {kind:'aborted'}>)` switches exhaustively: problem → its code's copy; network → `Calculator service is unreachable`; timeout → `Calculator service timed out`; unexpected → `Something went wrong`. `requestId` is carried only for a problem whose `requestId` matches the request-ID pattern `^[A-Za-z0-9._-]{1,128}$`: an empty one (F1), an over-long one, or one with spaces, control or bidirectional characters is treated as unavailable. Every request ID the edge or the service emits matches it, so nothing legitimate is lost. The returned object has only `message` and, when available, `requestId`.

D10 — **History codec.** `decodeHistory(raw: string | null)`: `null`, `""`, more than 65,536 UTF-16 code units, invalid JSON, a non-object or array envelope, `version !== 1` (number), `entries` not an array, any malformed entry, or a duplicate ID → `[]`. An entry is a non-null non-array object whose own properties are: `id` a string of 1–128 characters, `operation` an `OperationName`, `operands` an array of exactly `OPERATIONS[operation].arity` contract Decimals, `result` a contract Decimal, `inexact` a boolean; unknown properties are dropped by rebuilding the entry from these five. Only own properties are read (`Object.hasOwn`), so `__proto__` keys and inherited names never satisfy a field. Valid lists longer than 20 keep the first 20 in order. Wrapped so it never throws. Subnormal-looking but syntactically valid results are accepted (validation is syntax and length only). `encodeHistory(entries)`: the first 20 entries, each rebuilt with the five fields in a fixed order, inside `{"version":1,"entries":[…]}` via `JSON.stringify`, deterministic; entries that `decodeHistory` would reject (bad ID, operands, arity, result, or an ID already seen) are skipped, so a stored value always decodes to the list that was encoded and one bad in-memory entry can never empty the persisted history on the next load. The codec never touches storage.

D11 — **`createInitialState(history = [])`** returns the initial state with a frozen copy of at most the first 20 supplied entries; no storage read.

D12 — **Immutability.** States, requests, operands and history arrays produced by the reducer are frozen (`Object.freeze`, shallow; entries are built from frozen parts). Tests deep-freeze fixtures and assert previous states are untouched.

D13 — **Boundaries test.** `boundaries.test.ts` reads the model's source files as raw text (Vite `import.meta.glob(…, { query: '?raw', import: 'default', eager: true })`) and fails on a non-type import from outside the model (anything other than `import type` from `@/shared/api/types` or relative model files), on React/DOM/IO identifiers (`react`, `window`, `document`, `localStorage`, `sessionStorage`, `fetch`, `setTimeout`, `setInterval`, `Date`, `Math.random`, `crypto`) and on the arithmetic primitives of RF-UI-05 (`Number(`, `Number.`, `parseFloat`, `parseInt`, `BigInt`, `Intl.`, `eval`, `Math.`). Production files only; tests excluded.

D14 — **Keypad table and lookup.** `KEYPAD` has 23 frozen `KeyDefinition`s in row-major order (`id`, `label`, `ariaLabel`, `command`, `variant`, `row`, `column`, `rowSpan`, `bindings`), ids `all-clear`, `clear-entry`, `backspace`, `divide`, `sqrt`, `power`, `percentage`, `multiply`, `digit-7`…, `subtract`, `add`, `equals`, `sign`, `digit-0`, `decimal`; bindings are `KeyboardEvent.key` values (`Escape`, `Delete`, `Backspace`, `/`, `r`, `^`, `%`, `*`, `-`, `+`, `Enter`, `=`, `n`, digits, `.`, `,`). `commandForKey(key)` reads a `Map` built from `KEYPAD` bindings only (case-sensitive; `__proto__`, `constructor`, Space, `R`, `N` → `undefined`). `actionForCommand` is an exhaustive `switch` with no default.
