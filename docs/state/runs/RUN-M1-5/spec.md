## Design decisions

D1 — **Operation metadata in one table.** `OPERATIONS` maps every `OperationName` to `{ symbol, arity }` with the contract symbols, `satisfies Record<OperationName, …>`; `BinaryOperation`/`UnaryOperation` are `Extract`s of `OperationName`, with a compile-time check that they partition it (a new contract operation fails the type check until it is classified). Display, history text, the codec's arity check and the keypad all read this table. The power key's label stays `xʸ` (RF-UI-01); its expression symbol is the catalog's `^` (`2 ^ 10 = 1024`).

D2 — **Unchanged → same object.** Every action that changes no field returns the previous state object (`toBe`), not only the ignored actions of the guards: `=` with no pending operator, ⌫ or a digit beyond the cap, a second decimal point, ± on `"0"`, operator replacement with the same operator, C or AC on a state already in that shape, clear history on an empty history (the transition keeps the existing array). Implemented once: the reducer compares the candidate with the input field by field (`Object.is`) before returning. This keeps React bail-outs and the identity tests meaningful.

D3 — **Guard order.** (0) `historyRecalled` with a value that is not a contract Decimal returns the state in every status (D6); (1) a completion (`calculationSucceeded`/`calculationFailed`) whose `request` is not the very object in `state.request` (identity, `!==`), including `state.request === null`, returns the state — completions carry the request descriptor they answer, so a late completion of a request dropped by AC is ignored even when the new request reuses its number (RF-UI-04 «including after AC restarts request IDs», UC-UI-01 E5); (2) `status === 'busy'` and the action is not AC or a completion → state; (3) `status === 'error'`: digit, decimal point and recall reset (initial state, history kept, `nextRequestId` 1) and then apply in the reset state; C and AC both do that same full reset; clear history empties history and stays in error; everything else → state; (4) the transition table. Invariants (tested over generated sequences): `request !== null` ⇔ `status === 'busy'`; `error !== null` ⇔ `status === 'error'`; `entryMode === 'operand'` ⇒ `pendingOperator !== null` and `entry === accumulator`.

D4 — **Transitions (RF-UI-03, RF-UI-04, owner answer above).** `entryMode` has three values: `typing` (being edited), `fresh` (a finished value — result, recall — that the next digit replaces), `operand` (the entry is the stored left operand, shown right after a binary operator or a chained result; the next digit replaces it and another binary operator replaces the pending operator). Editing treats `fresh` and `operand` alike. Digit when fresh/operand: `entry = d`, typing, `inexact = false`. Decimal when fresh/operand: `"0."`, typing, `inexact = false`. ± toggles the leading `-` (not on `"0"`; not when the result would exceed 128 characters); `inexact` unchanged; typing and fresh keep their mode, `operand` becomes `fresh` (the entry is no longer the stored operand). ⌫ when fresh/operand: no-op. C: `entry "0"`, typing, `inexact false`, operator and accumulator kept (only reachable in idle). AC: initial state, history kept, `nextRequestId` 1. Binary with pending operator and entry `operand` → replace the operator (no request); with pending and typing or fresh → issue `{pendingOperator, [accumulator, toOperand(entry)], chain(op)}`; with none pending → `accumulator = entry = toOperand(entry)` (`"12."` shows as `12`), `pendingOperator = op`, mode `operand` (`inexact` unchanged: the value on screen is still the same). Unary → issue `{op, [toOperand(entry)], replaceEntry}` (pending operator and accumulator kept). `=` with `pendingOperator !== null && accumulator !== null` → issue `{pendingOperator, [accumulator, toOperand(entry)], complete}` (`5 + =` → add `["5","5"]`); otherwise no-op (no repeat-last-operation). Recall → `entry = value`, fresh, `inexact false`, operator kept. Success, by the captured request's continuation — complete: entry = result, accumulator and operator null, fresh; chain(op): entry = accumulator = result, operator `op`, mode `operand`; replaceEntry: entry = result, fresh; all: `inexact = payload.inexact`, idle, `request null`, history entry prepended (D5), capped at 20. Failure: error status, `error = payload`, request, accumulator and operator null, entry `"0"`, fresh, `inexact false`, history unchanged. Issue = `request {id: nextRequestId, operation, operands (fresh frozen array), continuation}`, `nextRequestId + 1`, busy, `error null`.

D5 — **History entry content.** Operation and operands from the captured request (what was asked), result and inexact from the payload; `id` = the action's `historyId`. The reducer does not compare `payload.operation` with the request (the client already guarantees it). Equal calculations stay separate entries. A `historyId` that is empty, longer than 128 characters or already present in the history still applies the result but adds no entry (the list stays a valid, uniquely keyed, encodable history).

D6 — **Recall value is checked.** `historyRecalled` with a value that is not a contract Decimal (≤ 128 characters) returns the state unchanged in every status, before any other guard. Values come from the codec or the API, both already validated; the check keeps the entry invariant — every entry `toOperand`s to a contract Decimal — independent of the caller.

D7 — **Entry-editing table (RF-UI-03).** Typing-mode entries are always plain: scientific values only enter as results or recalls (fresh), a digit or decimal point replaces them, ⌫ ignores them, ± only edits the sign. The exported functions behave as follows on their own:

| Function | Input | Output |
|---|---|---|
| `appendDigit` | `"0"`, d | d (`"0"`+`"0"` → `"0"`) |
| | `"-0"`, d | `"-"`+d |
| | 34 characters `0`–`9` already (the `0` of `0.` counts) | unchanged |
| | an entry with `e`/`E` | unchanged |
| | otherwise | entry + d (`"0."`+`"5"` → `"0.5"`, `"-12.0"`+`"0"` → `"-12.00"`) |
| `appendDecimalPoint` | entry containing `.`, `e` or `E` | unchanged |
| | otherwise | entry + `.` (`"0"` → `"0."`, `"-12"` → `"-12."`) |
| `toggleSign` | `"0"` | `"0"` |
| | leading `-` | without it (`"-12"` → `"12"`, `"-0"` → `"0"`, `"-2.5e-10"` → `"2.5e-10"`) |
| | 128 characters, no `-` | unchanged (would exceed the contract length) |
| | otherwise | `"-"` + entry (`"0."` → `"-0."`, `"1e+21"` → `"-1e+21"`) |
| `backspace` | any | last character dropped; `""`, `"-"`, `"-0"` → `"0"` (`"12.3"` → `"12."`, `"-5"` → `"0"`, `"-0.1"` → `"-0."`, `"-0."` → `"0"`) |
| `toOperand` | trailing `.` | without it (`"12."` → `"12"`, `"-0."` → `"-0"`) |
| | otherwise | unchanged (`"1e+21"`, `"1.2300"`) |

The digit cap counts characters `0`–`9`, not significant digits.

D8 — **Formatting is presentation only.** `formatEntry`: a leading `-` becomes U+2212; a value containing `e`/`E` is returned ungrouped (exponent sign stays ASCII); otherwise the integer part is grouped with `,` by a string regex, the fraction (with its trailing zeros) and an unfinished `.` kept. `selectDisplay`: `value = formatEntry(entry)`; `expression = formatEntry(accumulator) + " " + symbol` when both accumulator and pending operator are non-null, else `""`; `size` by `value.length` (U+2212 and commas counted, the `≈` marker excluded): ≤ 10 `xl`, ≤ 16 `lg`, else `md`; `inexact`, `busy` (`status === 'busy'`), `error` copied. `historyExpression`: binary `a sym b = r`, sqrt `√a = r`, percentage `a% = r`, with `≈` instead of `=` when inexact, every number through `formatEntry`. The UI builds `Use result <formatEntry(result)>`.

D9 — **Error copy.** `PROBLEM_MESSAGES satisfies Record<ProblemCode, string>` with an explicit entry for all 13 codes (RF-UI-08 copy; `NOT_FOUND`, `UNKNOWN_OPERATION`, `METHOD_NOT_ALLOWED`, `PAYLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`, `INTERNAL_ERROR` → `Something went wrong`). `toCalculatorError(error: Exclude<ApiError, {kind:'aborted'}>)` switches exhaustively: problem → its code's copy; network → `Calculator service is unreachable`; timeout → `Calculator service timed out`; unexpected → `Something went wrong`. `requestId` is carried only for a problem whose `requestId` matches the request-ID pattern `^[A-Za-z0-9._-]{1,128}$`: an empty one (F1), an over-long one, or one with spaces, control or bidirectional characters is treated as unavailable. Every request ID the edge or the service emits matches it, so nothing legitimate is lost. The returned object has only `message` and, when available, `requestId`.

D10 — **History codec.** `decodeHistory(raw: string | null)`: `null`, `""`, more than 65,536 UTF-16 code units, invalid JSON, a non-object or array envelope, `version !== 1` (number), `entries` not an array, any malformed entry, or a duplicate ID → `[]`. An entry is a non-null non-array object whose own properties are: `id` a string of 1–128 characters, `operation` an `OperationName`, `operands` an array of exactly `OPERATIONS[operation].arity` contract Decimals, `result` a contract Decimal, `inexact` a boolean; unknown properties are dropped by rebuilding the entry from these five. Only own properties are read (`Object.hasOwn`), so `__proto__` keys and inherited names never satisfy a field. `operation` is an own key of `OPERATIONS` (`constructor`, `toString`, `__proto__` rejected). Valid lists longer than 20 keep the first 20 in order; the decoded array and every decoded entry (and its operands) are frozen. Wrapped so it never throws. Subnormal-looking but syntactically valid results are accepted (validation is syntax and length only). `encodeHistory(entries)`: first drops the entries `decodeHistory` would reject (bad ID, operation, operands, arity, result, or an ID already seen earlier in the list), then takes the first 20 of the rest, each rebuilt with the five fields in a fixed order, inside `{"version":1,"entries":[…]}` via `JSON.stringify`, deterministic. So a stored value always decodes to that filtered, capped list, and one bad in-memory entry can never empty the persisted history on the next load. The codec never touches storage.

D11 — **`createInitialState(history = [])`** returns `entry "0"`, `entryMode "typing"`, null accumulator, operator, error and request, `inexact false`, `status "idle"`, `nextRequestId 1`, and a frozen copy of at most the first 20 supplied entries; no storage read.

D12 — **Immutability.** States, requests, operands and history arrays produced by the reducer are frozen (`Object.freeze`, shallow; entries are built from frozen parts). Tests deep-freeze fixtures and assert previous states are untouched.

D13 — **Boundaries test.** `boundaries.test.ts` reads the model's production source files as raw text (Vite `import.meta.glob<string>(['./*.ts', '!./*.test.ts', '!./testing.ts'], { query: '?raw', import: 'default', eager: true })`), strips comments, and fails on any `import`/`export … from` or dynamic `import(` other than `import type` from `@/shared/api/types` and relative model files, and, as whole words (`\b` boundaries, so `evaluate` or `documented` do not match), on React/DOM/IO identifiers (`react`, `window`, `document`, `localStorage`, `sessionStorage`, `fetch`, `setTimeout`, `setInterval`, `Date`, `Math.random`, `crypto`) and on the arithmetic primitives of RF-UI-05 (`Number(`, `Number.`, `parseFloat`, `parseInt`, `BigInt`, `Intl.`, `eval`, `Math.`). It also asserts the glob found exactly the expected production files, so it cannot pass vacuously. `testing.ts` (deep freeze and dispatch helpers) stays in the model directory, imported only by tests: moving it to `src/test/` would leave this run's ownership and make every later change there a package-wide input of the tiers; it is fully exercised by the tests, so it does not lower coverage.

D14 — **Keypad table and lookup.** `KEYPAD` has 23 frozen `KeyDefinition`s in row-major order (`id`, `label`, `ariaLabel`, `command`, `variant`, `row`, `column`, `rowSpan`, `bindings`), ids `all-clear`, `clear-entry`, `backspace`, `divide`, `sqrt`, `power`, `percentage`, `multiply`, `digit-7`…, `subtract`, `add`, `equals`, `sign`, `digit-0`, `decimal`; bindings are `KeyboardEvent.key` values (`Escape`, `Delete`, `Backspace`, `/`, `r`, `^`, `%`, `*`, `-`, `+`, `Enter`, `=`, `n`, digits, `.`, `,`). `commandForKey(key)` reads a `Map` built from `KEYPAD` bindings only (case-sensitive; `__proto__`, `constructor`, Space, `R`, `N` → `undefined`). `actionForCommand` is an exhaustive `switch` with no default.
