### Findings of OPS-IMAGE-01 — Embedded web handler and the API image (2026-10-22)
- (a) **OPS** [topic: deployment-infra, security-privacy, edge-proxy] [type: rule] — Rule as built (`backend/internal/web`): `newHandler(fs.FS)` maps `/` to `index.html` and any other `r.URL.Path` to a file name that must pass `fs.ValidPath`, have no segment starting with `.` and be a regular file; a directory (with or without a trailing slash), a missing file, a dotfile (`dist/.gitkeep` included) or an invalid path is answered by `httpx.NotFound` — the NOT_FOUND problem of RF-API-05 with the `no-store` and the API CSP the router and `SecureHeaders` already set — never a listing, a redirect or an HTML fallback. For an existing file the five RNF-SEC-03 headers are set with `Set` (so each has one value and the router's `no-store` and API CSP are replaced; `Cross-Origin-Resource-Policy: same-origin` from `SecureHeaders` stays), `Content-Type` comes from a fully explicit extension table (never `mime.TypeByExtension`, which layers the host's `/etc/mime.types`; unknown → `application/octet-stream`), a strong ETag (`"` + 16 hex characters of the file's SHA-256 + `"`) is computed once at construction, and `http.ServeContent` (zero modification time, so no `Last-Modified`) provides HEAD, `Range` and `If-None-Match`. `Cache-Control` is decided at `WriteHeader` by the final status: `public, max-age=31536000, immutable` only under `/assets/` with 200, 206 or 304 (source maps included), `no-cache` for everything else (a 412 or 416 included: Go keeps a pre-set header on a 412 and strips it on a 416, so a prefix rule would send `immutable` with an error). A read failure on a file that is not seekable is the INTERNAL_ERROR problem before any file header is set. `Handler()` is nil without `embedui`; with it, `fs.Sub(embed.FS "all:dist", "dist")`. A test compares the five header values with `deploy/nginx/security-headers.conf` (found by walking up from the working directory), so the edge and the embedded handler cannot drift.
- (b) **OPS** [topic: deployment-infra, security-privacy] [type: rule] — Rule as built (`backend/Dockerfile`): repository root as context; build stage `golang:1.27.3-alpine3.24` and runtime `gcr.io/distroless/static-debian13:nonroot`, both by tag and digest; `GOTOOLCHAIN=local`, `CGO_ENABLED=0`, `-trimpath -ldflags "-s -w -X …/buildinfo.Version=$VERSION -X …/buildinfo.Commit=$COMMIT"`, modules downloaded in their own cached layer; no `embedui` tag (API-only); `USER 65532:65532`, `EXPOSE 8081` only (the service also listens on `:9091`, but `docker run -P` publishes every exposed port and the admin port is never published, RNF-SEC-04), healthcheck `["/calculator","healthcheck"]`. Measured: cold-ish build 53 s (base images pulled first), layers sum to 16.5 MB (binary 10.7 MB), compressed content 5.3 MB, while `docker images` reports 21.8 MB under the containerd image store's snapshot accounting — RF-OPS-05's «under 20 MB» is met by the layer sum, not by that listing.
- (c) **OPS** [topic: deployment-infra] [type: debt] [target: OPS-STACK-01] — A binary built with `-tags embedui` while `backend/internal/web/dist` holds only `.gitkeep` starts and answers every app path with the NOT_FOUND problem (`go vet` and `go test -tags embedui` rely on this). The root `Dockerfile` must therefore assert `dist/index.html` and `dist/theme-init.js` exist after copying the built app into `backend/internal/web/dist/` and before `go build -tags embedui` (as `frontend/Dockerfile` asserts its output), and must copy into the directory without removing `dist/.gitkeep` from the checkout (`//go:embed all:dist` needs at least one file).
- (d) **OPS, API** [topic: deployment-infra, api-contract, live-verification] [type: note] — In the all-in-one image the catch-all `/` is the embedded handler, so unmatched paths differ from the API-only build: a missing app file or directory answers the NOT_FOUND problem (the edge answers nginx's own 404 page there), and `POST` or any other method on an unknown path answers 405 with `Allow: GET, HEAD` (the router's `httpx.Methods` on `/`) where the API-only build answers 404. API responses (`/api/*`, probes) carry the API header set of RF-API-08 in that image, without `Permissions-Policy` or `Cross-Origin-Opener-Policy`; header assertions for RNF-SEC-03 therefore target app files. `OPS-E2E-01` and `scripts/smoke-aio.sh` should expect exactly this.
- (e) **OPS** [topic: edge-proxy, deployment-infra] [type: note] — Responses ServeContent writes itself: the 412 has an empty body and the 416 a fixed plain-text body (`invalid range: failed to overlap`), neither with client input, both `nosniff` (RNF-SEC-02 holds). The embedded handler does not compress (the edge does: `gzip` on text types), so the all-in-one image sends the bundle uncompressed; a trade-off for the README, not a defect.

### Findings of OBS-LOG-01 — Access-log levels and field bounds (2026-10-22)
- (a) **OBS** [topic: observability, security-privacy, reliability-errors] [type: rule] — Rule as built (`httpx`, `httpapi`): `RequestInfo` carries an optional level (unexported `level`/`levelSet`) set through `httpx.SetAccessLevel(ctx, level)` (a no-op outside `RequestContext`); `logAccess` uses the handler's level when set, else `error` for 5xx and `info` otherwise, and never reads the path. The readiness handler sets `info` only on its draining 503, immediately before writing it. `Recover` clears any level on every panic, `http.ErrAbortHandler` included, before re-panicking or answering, so a handler that set `info` and then panicked or aborted is still logged at `error`. `path` (`r.URL.Path`, decoded) and `user_agent` are cut to their first 256 characters (runes) by `truncateChars`, which stops walking at the 257th rune and returns the string itself when it fits; a cut always falls on a rune boundary, an invalid byte counts as one character, nothing is appended. The bound is on characters: the raw field is at most 1024 bytes and JSON escaping can inflate control or invalid bytes to about six bytes per character. `remote_addr`, `method`, `route`, `status`, `bytes` and `duration_ms` are unchanged. Proven over a socket too: with `CALC_SHUTDOWN_DRAIN=4s` and SIGTERM, ten draining `/readyz` 503 access lines are all `INFO` and the whole log has zero `ERROR` lines (`evidence/sigterm-live.txt`).
- (b) **OBS** [topic: observability, security-privacy] [type: debt] [target: OBS-backlog] — `method` is logged raw and is bounded only by the HTTP token grammar and the 16 KiB header limit, so a client can still write a method of up to about 16 KiB into every access line (owner decision U20 bounds `path` and `user_agent` and keeps every other field unchanged). Options for the owner: truncate it the same way (256 characters), or log `OTHER` for a method outside the standard set as the metrics label already does.
- (c) **OBS** [topic: observability] [type: note] — `SetAccessLevel` can lower any 5xx: the handler that answers owns the level of its line (U19). The only fallback that could turn a readiness response into a 500 after the level is set is `WriteJSON`'s marshal-failure path for a struct of three strings (`respond.go`, documented unreachable); no check ties the level to the status the handler intended. Reviewed and accepted.
