## 3. UI-HOOKS-01 design

Files (all under `frontend/src/`): `features/calculator/hooks/{historyStorage,useCalculator,useKeyboardShortcuts,useDelayedBusy,useMediaQuery,historyId}.ts` + tests; `shared/theme/{theme,useTheme}.ts(x)` + tests and the moved `theme-init.test.ts`; `test/{calculatorFake,matchMedia}.ts`.

### 3.1 `useCalculator` (the single place that starts calculation IO)
- `useReducer(calculatorReducer, undefined, () => createInitialState(loadHistory()))`; `loadHistory()` = `decodeHistory(safeStorage.get(HISTORY_STORAGE_KEY))`.
- One effect keyed on `[api, state.request]`: for a non-null request, `AbortController`, effect-instance `active` flag, `api.calculate(request.operation, request.operands, {signal})`; on settle: ignore when `!active || signal.aborted`; `ok` → `calculationSucceeded` with **the captured `request` object** and a fresh `historyId`; `kind === 'aborted'` → nothing; any other error → `calculationFailed` with `toCalculatorError(error)`. Cleanup: `active = false; controller.abort()`. The call is `void api.calculate(…).then(…)` (satisfies `no-floating-promises`); no `.catch` (the client never rejects; a broken fake must surface, not be reclassified as a network error). `active` and `signal.aborted` are defence in depth: the reducer's identity guard (`reducer.ts` `action.request !== state.request`) already makes a stale completion a no-op, so the observable proof is that a stale completion **never reaches the reducer** (a test wraps `calculatorReducer` with a spy via `vi.mock` + `importActual` and counts completion actions).
- The dependency list never contains `state.entry` or the state object; `eslint-plugin-react-hooks` stays on without disables.
- History id: `historyId.ts` `newHistoryId()` → `crypto.randomUUID()` when it is a function, else 16 bytes of `crypto.getRandomValues` as hex (`randomUUID` exists only in secure contexts; the app can be served over plain HTTP on a LAN address, where calling it throws and the completion would be lost), else a timestamp + counter string. Always 1–128 characters; unique within a history; **never throws** (guards `typeof crypto`, wraps in `try/catch`, since a throw inside `.then` would leave the screen busy until AC). Used only as a React key.
- Persistence: a second effect on `state.history` calls `saveHistory(history)` (`safeStorage.set(HISTORY_STORAGE_KEY, encodeHistory(entries))`) **only when the history is no longer the initial array**: `const loaded = useRef(state.history)` created right after `useReducer` (the state's own array, not `loadHistory()`'s: `createInitialState` copies it) and `if (state.history === loaded.current) return` in the effect: a mount, a StrictMode replay or a corrupt/blocked read never rewrites storage; the first success or a clear does (clearing writes `{version:1,entries:[]}`). Persistence failures are swallowed by `safeStorage`.
- Controller: `{display, history, busy, execute, recall, clearHistory}`; `display = {...selectDisplay(state), showSpinner}`; `execute(command)` dispatches `actionForCommand(command)`; `recall(value)` → `historyRecalled`; `clearHistory()` → `historyCleared`; all three `useCallback` over the stable `dispatch`, so they are referentially stable.
- `busy` is `state.status === 'busy'`. `showSpinner = useDelayedBusy(busy, state.request)`.

### 3.2 `useDelayedBusy(busy, request)` (RF-UI-07)
- State holds `shownFor: CalculationRequest | null`. An effect on `[busy, request]` starts a 150 ms timer when `busy && request !== null`, whose callback sets `shownFor = request`; cleanup clears the timer. The hook returns `busy && request !== null && shownFor === request`: a new request object (even with a reused numeric id) cannot inherit the previous spinner, because identity is compared in the same render; completion/AC hides it in the render that clears `busy`. The state is only set from the timer callback (no synchronous set-state-in-effect).
- Value dimming is not here: the display dims on `busy` immediately.

### 3.3 `useKeyboardShortcuts(execute)` (RF-UI-02, UC-UI-01 E9/E10, UC-UI-04 E3)
One `window` `keydown` listener (effect on `[execute]`, removed with the same function). Order of guards:
1. ignore when `event.defaultPrevented`, `ctrlKey`, `metaKey`, `altKey`, `event.isComposing`, or `event.keyCode === 229` (Safari reports the keydown that confirms an IME candidate with `isComposing === false` and key `Enter`; `keyCode` is deprecated, so the one use carries a one-line justified lint disable). Shift is allowed.
2. resolve the target element (an `Element`, else the parent element of a `Node`, else none). Ignore when it is inside an **editable** control: `textarea`, `select`, `input` whose type is textual (not `button|checkbox|radio|range|color|file|image|reset|submit`), `[contenteditable]` not `false`, `[role=textbox|searchbox|combobox]`. Decision (differs from the plan's blanket `input`): theme radios and other non-textual inputs are not editable, so digits and operators keep working after the visitor picks a theme (RF-UI-02 lists radios only for Enter/Space).
3. for `Enter` or ` `: ignore when the target is inside a native activation control: `button`, `summary`, `a[href]`, `input`, `select`, `[role=button|radio|checkbox|switch|menuitem|tab|link]`. (Space is unbound anyway; the rule keeps it correct if a binding is added.) `=` is not an activation key and stays handled on a focused button.
4. `commandForKey(event.key)`; if undefined return (no `preventDefault`, so Space/Tab/arrows/unknown keys keep their native behaviour); else `preventDefault()` and `execute(command)`. Repeats are not filtered.
No `stopPropagation`.

### 3.4 Theme (RF-UI-11)
- `theme.ts`: `Theme`, `THEME_STORAGE_KEY`, `readTheme()` (safeStorage; only `system|light|dark`, else `system`), `applyTheme(theme)` (`setAttribute('data-theme', 'light'|'dark')` or `removeAttribute`), `writeTheme(theme)` (safeStorage).
- `useTheme()`: lazy `readTheme()`, `setTheme(theme)` = state set + `writeTheme` (persisted in the event path, not on mount), an effect `applyTheme(theme)` on `[theme]`. Selecting `system` stores `system` and removes the attribute (never `data-theme="system"`). No JS listener for the OS preference (the media query governs).
- `theme-init.test.ts` moves to `shared/theme/` and gains a **consistency** table: for each stored value (`light`, `dark`, `system`, junk, empty, absent, throwing storage) the real script and `applyTheme(readTheme())` leave the same attribute.

A controllable fake lives in `test/matchMedia.ts` (the shared `setup.ts` is not touched: it is a package-wide input of the tiers); every test using it calls `restore()` and every fake-timer test `vi.useRealTimers()` in `afterEach` (`restoreMocks: true` undoes neither).

## 4. UI-SCREEN-01 design

### 4.1 Shape brief (Impeccable `shape`, mode **Operate**, established world)
Autonomy substitution: the owner decided (U25) that this surface is shaped and built from the U5 baseline without an owner stop, and the structure, tokens, copy and states are normative in `PRODUCT.md`, `DESIGN.md` and RF-UI-01/06/07/08/10/11/12/13, so no discovery interview was run; the brief below records the settled reading. It is persisted as the surface brief `calculator` (`impeccable surface-brief`). The visual world is not reopened (DESIGN.md: «The Precision Instrument»; token values change only on a measured contrast failure). Comps (Codex imagery, U25 «may») are not produced: a pixel-pinned comp adds nothing to a layout fully specified by tokens and a numeric budget, and the real-browser screenshots are the evidence.
- **Job and audience:** an anonymous visitor in short bursts, on phone or desktop, who must enter a calculation, trust the server's exact result, understand a failure, and reuse earlier results.
- **Direction:** a dark readout in both themes above a 4 × 6 keypad on a quiet tonal card; history one tap away; theme as a segmented native radio group in the header. Colour as intent only (blue = operate, deeper blue = evaluate, amber = where the keyboard is).
- **Hierarchy:** value (xl → lg → md by length) ≫ pending expression ≫ keypad ≫ history. Focal moment: the value changing from dimmed to the exact answer.
- **States:** initial; typing; pending expression; busy (digits dimmed immediately, spinner after 150 ms); exact and inexact (`≈`) result; 34-digit result wrapping; error with and without `Ref`; empty/full (20) history; each theme; reduced motion.
- **Anti-goals:** no icons, no card grids, no gradients, no shadows or motion on keys, no inline styles, no extra chrome, no animated numbers.

### 4.2 Components (`features/calculator/ui/`, `shared/theme/`, `app/`)
Contracts as in the plan (Task 14): `Calculator`, `Display`, `Keypad`, `KeyButton`, `HistoryPanel`, `ThemeToggle`, `App`; `features/calculator/index.ts` exports only `Calculator`. Decisions:
- **Display:** the display root carries `aria-busy`. Inside: the expression line (text, secondary); a persistent empty-able `role="alert"` container holding the error message and, only when `requestId` is present, `Ref: <requestId>` as text; the numeric `<output aria-live="polite" aria-atomic="true" aria-label="Result">`, emptied while an error shows (the alert is a sibling, so one error is announced once). When `inexact`, **inside the `<output>`** and before the digits: `<span class=approx title="Rounded to 34 significant digits"><span aria-hidden>≈</span><span class="visually-hidden">Rounded to 34 significant digits. </span></span>`, so the polite atomic live region announces the explanation with the digits; the output's text content therefore contains the sentence when inexact. The `≈` and the expression stay at full opacity while busy; only the digits span dims (opacity 0.6). Spinner: a 1 rem ring (CSS only), `aria-hidden`, rendered only when `showSpinner`, together with the static visually-hidden text `Calculating` (rendered only with the spinner, never while idle). Size class from `model.size`; `overflow-wrap: anywhere` on the value, **the expression line (a 34-digit accumulator is ~45 characters), the `Ref:` line (up to 128 characters) and the history rows (two 34-digit operands)**, with `min-width: 0` on every grid/flex child; tabular numerals; the readout is right-aligned; the `Ref:` line is Readout Grey in the label style (not the error colour); error colour `--color-display-danger`; the readout keeps a minimum height of the expression line plus one xl line.
- **Keypad / KeyButton:** `role="group"` `aria-label="Keypad"`, CSS Grid `repeat(4, minmax(0, 1fr))` gap `--space-2`; `KEYPAD` rendered once in order, `definition.id` as key; placement from finite classes (`row1…row6`, `col1…col4`, `span2`) chosen by lookup tables from `row`/`column`/`rowSpan`; native `<button type="button" aria-label>`; `onClick` executes the command; `onMouseDown` prevents default (focus never moves on a click; Enter then evaluates); never disabled; **the same `mousedown` default-prevention applies to the history rows and `Clear history`** (a mouse click on them must not leave focus there, or the next Enter would re-press that button instead of evaluating; the `summary` keeps native toggle/focus and the theme radios keep native focus, both accepted: RF-UI-02 names them); variant fills with hover/active `color-mix(…, var(--color-text) 8%/16%)`; label colours from tokens; min size `--key-size`; transition on background only (global reduced-motion rule applies).
- **HistoryPanel:** one `<details>`/`<summary>History</summary>` (≥ 48 px), `open` controlled as derived state `open = override ?? isWide`, with the user's `override: boolean | null` **discarded whenever the breakpoint changes** (the last seen `isWide` is kept in state and compared during render, the documented «adjust state while rendering» pattern; plan review finding 9: a narrow→open→wide→narrow round trip must return to the collapsed default), where `isWide = useMediaQuery('(min-width: 768px)')` (the CSS media query is also written in `px`, not `rem`, so JS and CSS agree) and the override `{wide, open}` is set by `onToggle` from `event.currentTarget.open` (not `newState`: two quick taps queue two toggle events; `toggle` also fires on mount/programmatic changes, a harmless extra render; tests `await` it because jsdom fires it asynchronously); crossing the breakpoint returns to the default for that width; unrelated renders never change it. `<ol>` newest first, each `<li>` a full-width native button with text `historyExpression(entry)`, `aria-label="Use result ${formatEntry(entry.result)}"`, `onClick → recall(entry.result)` (raw), key = `entry.id` (never rendered in text/attributes); empty state `No calculations yet`; `Clear history` button shown only when there are entries (function-key styling, ≥ 48 px; rows ≥ 48 px with the `--color-surface-raised` hover tint); the click sets a `pendingFocus` ref and an effect on `entries.length` focuses the summary when the list became empty (so a clear ignored while busy, which changes nothing, does not move focus; a stale flag is harmless because the list can only empty through that click).
- **ThemeToggle:** `<fieldset role="radiogroup">` (name `Theme` from a visually-hidden `<legend>`; `min-width: 0`), three `<label position:relative>` segments wrapping native `<input type="radio">` (shared `name` from `useId`) + text `System | Light | Dark`; the input is visually hidden but focusable; checked state = operator fill + weight 600 (not hue alone); segments ≥ 48 × 48 px; the focus ring shows on the segment (`input:focus-visible + span`).
- **Calculator:** `useCalculator()` + `useKeyboardShortcuts(execute)`; layout: one `div` with the card (display + keypad) and the `HistoryPanel`.
- **App:** `<header>` (`h1` `Calculator` + `ThemeToggle`; `flex-wrap: wrap`, because the title plus three 48 px segments is ~280 px of the 288 px available at 320 px) and `<main>` (`Calculator`); `min-height: 100dvh`; mobile single column, ≥ 768 px two centred columns 22.5rem + 18rem with `--space-6` gap; gutter `--space-4`; keypad budget rule (card padding `--space-4` + 1 px border, keypad itself unpadded).
- **main.tsx:** `createCalculatorApi({ baseUrl: resolveBaseUrl(import.meta.env.VITE_API_BASE_URL, window.location.origin) })` once, outside rendering; `StrictMode > CalculatorApiProvider > App`; explicit root check, no `!`.
- **CSS:** CSS Modules on the existing tokens; no new colour, no inline style attribute; `tokens.css`/`global.css` change only for a defect shown by measurement.
