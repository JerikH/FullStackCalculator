### Findings of OPS-ENV-01 — per-agent isolated environment (2026-10-22)
- (a) **OPS** [topic: testing-environment, deployment-infra] [type: rule] — Rule as built: `source scripts/ci/env.sh` (bash, after `eval "$(.workflow/bin/wf env --export)"`) derives every value from the agent identity, never from pre-set variables. The checkout kind comes from the `.wf-agent` file at the repository root (two levels above the script): a worker worktree requires `WF_AGENT` equal to that file's agent, `WF_INDEX ≥ 1`, an integer `WF_PORT_BASE` and `WF_PORT_END ≥ base + 3`; the main checkout accepts only `WF_AGENT` unset/`main` and `WF_INDEX` unset/`0` (both unset → defaults plus the E1 note). Main: web 8080, API `:8081`, admin `:9091`, Vite 5173, `http://localhost:8081`, `http://127.0.0.1:8080`, `fullstackcalculator`; worker base *b*: *b*, `:b+1`, `:b+2`, *b+3*, `fullstackcalculator-<agent lowercased, [^a-z0-9_-] → ->`. `PATH` gains the repository `bin/` first and `$HOME/.local/go/bin`, each once. Without Go, or on any identity error, it returns 1 and exports nothing; executed instead of sourced it exits 2; callers under `set -euo pipefail` keep running.
