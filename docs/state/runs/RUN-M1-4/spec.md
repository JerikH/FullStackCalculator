## OBS-METRICS-01 — Build info, request-aware logger and metrics

**Scope:** RF-OBS-05 (logger with `request_id`, JSON/text), RF-OBS-06 (custom registry, the five families, bounded labels, metrics middleware, calculator decorator), RF-OBS-09 (buildinfo), RNF-SEC-02 (no input-minted series). Registered follow-ups: «Findings of API-HTTPX-01» (e), «Findings of W1» (b).

**Missing:** `backend/internal/buildinfo/{buildinfo.go,buildinfo_test.go}`, `backend/internal/observability/{doc.go,logger.go,logger_test.go,metrics.go,metrics_test.go}`.

**Decisions:**
- `buildinfo`: `Version = "dev"`, `Commit = ""` set by `-ldflags -X github.com/JerikH/FullStackCalculator/backend/internal/buildinfo.Version|Commit`; `Get()` returns `{Version, commit(), runtime.Version()}`; the commit falls back to the first 12 characters of `vcs.revision` from `debug.ReadBuildInfo`, else `unknown`. The fallback is a pure helper over the build settings so the VCS branch is unit-tested (test binaries carry no VCS stamp).
- Logger: `NewLogger(w, level, format)` — JSON, or text when `format == "text"`; a context handler adds `request_id` from `httpx.RequestID(ctx)` to every record logged with a context that has one, and nothing otherwise; `WithAttrs`/`WithGroup` keep the wrapper.
- Metrics (custom registry, names, help texts and buckets as RF-OBS-06): `http_requests_total{method,route,status}`, `http_request_duration_seconds{method,route}`, `http_requests_in_flight`, `calculator_operations_total{operation,outcome}`, `calculator_build_info{version,commit,go_version}` = 1, plus the Go and process collectors.
- **Middleware records in a `defer`** (follow-up (e)): in-flight inc/dec, then a deferred function reads `httpx.Info(ctx).StatusOrOK()` and `Route` and observes counter and histogram. A request that unwinds with `http.ErrAbortHandler` (Recover after a started response, recorded as 500) is therefore counted as 500. Without `RequestContext` the route is `unmatched` and the status 200.
- Method label: `GET HEAD POST PUT PATCH DELETE OPTIONS` as themselves, anything else `OTHER`. Route label: the pattern from `httpx.Route` or `unmatched` (mux redirects). Status: the recorded integer status.
- Decorator: `InstrumentCalculator(c)` snapshots `c.Operations()` names; an unknown name is labelled `unknown`; outcome is `calc.Outcome(err)` (bounded, RF-CALC-10).

**Verification:** `go test -race -cover ./internal/buildinfo/ ./internal/observability/` ≥ 90 % each; exposition-text comparisons (`testutil.GatherAndCompare`) for `http_requests_total` (method `OTHER`), a panicking route behind `Recover` counted as 500 and a started-then-panicking route (ErrAbortHandler) counted as 500, `calculator_operations_total` (operation `unknown`, outcome `canceled` for `context.Canceled`), `calculator_build_info`; histogram series count; in-flight back to 0 after requests (also after an abort); logger tests for `request_id` presence/absence and level/format; the VCS fallback (long revision → 12 chars, missing → `unknown`, ldflags value wins). Mutation: move the observation out of the `defer` → the abort test fails.

**Scope:** UC-API-01, UC-API-02; RF-API-02, RF-API-03, RF-API-04 (full order: rule 1 before the body, rules 5–8), RF-API-05 (domain error → problem), RF-API-08, RF-API-09, the probe handlers of RF-OBS-02/03 (`Readiness` with `Drain()`), `GET /api/v1/openapi.yaml` with `Cache-Control: no-store` plus a regression test; U12 worst-case benchmark. **Decisions:**
- Consumer-defined `Calculator` interface (`Calculate`, `Operations`); `Deps{Calculator, Logger, Readiness, Build, Web}`; `NewRouter(Deps) http.Handler` registers method-less patterns, each wrapped in `httpx.Route(pattern, …)`: `/api/v1/operations` (GET), `/api/v1/operations/{operation}` (POST), `/api/v1/openapi.yaml` (GET), `/healthz` (GET), `/readyz` (GET), `/api/` → `NotFound`, `/` → `Methods{GET, HEAD: Web}` when `Web != nil`, else `NotFound`. Middleware is composed by `internal/app`.
- **Router default `Cache-Control: no-store`.** `NewRouter` returns the mux behind a one-line wrapper that sets `Cache-Control: no-store` before dispatch, so the mux's own 307 redirects under `/api/` also carry it (RF-API-08: every response under `/api/*`); handlers (`WriteJSON`/`WriteProblem`/spec) set it anyway; the embedded web handler of OPS-IMAGE-01 overrides it for app files.
- Every JSON response uses `httpx.WriteJSON(w, r, status, v)` — list, calculate, healthz, readyz and the draining 503 (follow-up W1 (b)).
- Calculate order (RF-API-04): (1) `PathValue("operation")` not in the snapshot of `Operations()` names → 404 `UNKNOWN_OPERATION` `operation %q is not supported; see GET /api/v1/operations`, body never read; (2–4) `httpx.DecodeJSON` into `struct{ Operands json.RawMessage \`json:"operands"\` }` (exact key; `[]`/`null` → `request body must contain a single JSON object`); (5) raw `operands` absent or `null` → `VALIDATION_FAILED` `one or more fields are invalid`, `{field: operands, reason: is required}`; (6) **not an array whose every element is a JSON string** (numbers, objects, a string, `[null]`, `["1", null]`) → same detail, reason `must be an array of decimal strings, e.g. ["2", "3"]` — decided because `json.Unmarshal` into `[]string` silently turns a `null` element into `""`, and the contract's `Decimal` is a string; (7) arity and (8) operand validation come from `calc.Calculate` and map to `VALIDATION_FAILED` with the arity message (detail and a single `operands` violation) or `one or more operands are invalid` with one `operands[i]` violation per bad operand (reason = the calc sentinel text; raw values never reflected).
- Domain mapping `problemFor(err, op)`: `DIVISION_BY_ZERO`, `UNDEFINED_RESULT`, `OVERFLOW` with `err.Error()` as the detail (the calc messages are the RF texts); unknown operation as in (1); **`context.Canceled`/`DeadlineExceeded` → `INTERNAL_ERROR` `an unexpected error occurred`, logged at `warn` as `calculation canceled`** (UC-API-02 E14: the client is gone; the contract has no other status; the outcome label `canceled` is counted by the decorator); anything else → `INTERNAL_ERROR`, logged at `error` with the error (never in the body, RF-API-11).
- Success: `200 {"operation","operands","result","inexact"}` echoing the operand strings unchanged.
- `serveSpec`: `Content-Type: application/yaml`, `Cache-Control: no-store` (adaptation), `Content-Length`, body byte-identical to `api.Spec`.
- Health: `Readiness{atomic.Bool}` with `Drain()`/`Draining()`; `/healthz` 200 `{"status":"ok",version,commit}` always; `/readyz` 200 `ready` or 503 `draining` (Health JSON, not a Problem, through `WriteJSON`).
- Contract tests (`pb33f/libopenapi-validator` v0.16.1 on `api.Spec`): every declared status the service emits is produced and validated as a response of its operation — list 200; calculate 200, 400 MALFORMED and VALIDATION_FAILED, 404 UNKNOWN_OPERATION, 413, 415, 422 ×3, 500 (failing calculator); openapi 200; healthz 200; readyz 200 and 503. A 405 (any path, incl. `/healthz`, `/readyz`, `/api/v1/openapi.yaml`) and the unmatched 404 have no operation for their method/path, so their bodies are validated against `#/components/schemas/Problem` and `Allow` is asserted («Findings of API-CONTRACT-01» (a)). Catalog names == `OperationName` enum in order; `httpx.Codes()` ⊆ `ProblemCode` enum and the two edge-only codes absent from `Codes()` (W1 (a): subset, not equality).
- U12: `BenchmarkCalculateWorstCase` in `bench_test.go` with the range-edge fractional powers measured in «Findings of CALC-OPS-01» (c): `9.999999999999999999999999999999999e6144 ^ 0.5`, `1e-6143 ^ 0.5`, `9.999…9e6144 ^ 0.9999999999999999999999999999999999`, `1e-6143 ^ 0.999…9`, `9.999…9e6144 ^ -0.999…9`, `1.5e-6143 ^ -0.999…9`, `-1 ^ 1e6144`; each case first asserts the call succeeds (an early validation error would measure nothing); budget < 50,000,000 ns/op each; `BenchmarkCalculate` unchanged.

**Verification:** `go test -race -cover ./internal/httpapi/` ≥ 90 %; the router table covers UC-API-01 E1–E3 and UC-API-02 E1–E14 with exact status, code, detail, `errors[]`, `instance`, `requestId` == header, `Content-Type`, `Cache-Control`, `Allow`; a repeated `operands` key decoded with the last occurrence; `OPERANDS` key → `unknown field "OPERANDS"`; `[null]`/`["1",null]`/`"12"` → rule 6; served YAML byte-identical with `no-store` (regression); mux redirect under `/api/` carries `no-store`; web handler mounted at `/` but not under `/api/`, `POST /` → 405. ## OBS-RUNTIME-01 — Configuration, lifecycle, admin listener and entrypoint

**Scope:** UC-OBS-01; RF-API-12, RF-OBS-01, RF-OBS-04, RF-OBS-07, RF-OBS-08, RF-OBS-02/03 (wired), RNF-REL-01 (drain). Registered follow-up: «Findings of API-HTTPX-01» (f). Creates `backend/internal/web/noembed.go`.

**Missing:** `backend/internal/config/{config.go,config_test.go}`, `backend/internal/app/{doc.go,app.go,main.go,probe.go,app_test.go}`, `backend/cmd/calculator/main.go`, `backend/internal/web/noembed.go`.

**Decisions:**
- `config.Load(lookup)` per RF-OBS-01 with `errors.Join` of every invalid variable (`NAME="value": reason`); addresses must split as host:port **with a numeric port 0–65535** (an empty or named port is rejected: `:` would silently bind a random port); `CALC_ADMIN_ADDR=""` disables the admin listener; level `debug|info|warn|error` (case-insensitive); format `json|text`; timeout > 0; drain ≥ 0; `CALC_PPROF` by `strconv.ParseBool`.
- `app.New(cfg, logger)` wires calc → metrics decorator → router (with `web.Handler()`) → chain **RequestContext → AccessLog → Metrics → Recover → SecureHeaders → router** (RF-API-12) through one unexported compose function that the end-to-end panic test reuses with a panicking router; binds both listeners before returning (bind errors surface from `New`; `:0` usable); the admin mux serves `GET /metrics` (promhttp over the custom registry) and, only with `EnablePprof`, `/debug/pprof/` (index, cmdline, profile, symbol, trace); the public mux never serves them.
- Servers: ReadHeader 5 s, Read 10 s, Write 15 s, Idle 60 s, MaxHeaderBytes 16 KiB, `ErrorLog` bridged to slog at warn.
- `Run(ctx)`: serves both; logs `server started` with both addresses; returns early with the error (after shutting the other down) if a server fails; on `ctx.Done()`: `Drain()`, log `shutdown started`, wait `ShutdownDrain`, then `Shutdown` both within `ShutdownTimeout` (one shared deadline); `shutdown complete`; a shutdown that exceeds the timeout returns an error.
- `Main(ctx, args, lookupEnv, stdout, stderr) int`: `calculator healthcheck` → `Probe` `http://<loopback for wildcard hosts>:<port>/healthz` with a 2 s client timeout, exit 0/1 — **an invalid configuration in healthcheck mode exits 1** (RF-OBS-08 «1 otherwise»); serve mode: invalid configuration → all problems on stderr, exit 2; unknown subcommand or extra arguments → usage on stderr, exit 2; startup or run failure → logged, exit 1; clean shutdown → 0. The logger is `observability.NewLogger(stdout, level, format)`.
- `cmd/calculator`: `signal.NotifyContext(SIGINT, SIGTERM)`; after the first signal `stop()` restores default handling so a second signal terminates immediately; `os.Exit(app.Main(...))`.
- `web/noembed.go`: `//go:build !embedui`, package doc comment, `Enabled = false`, `Handler()` returns nil.

**Verification:** `go test -race -cover ./internal/config/ ./internal/app/` (each ≥ 85 %): defaults, overrides, every invalid variable reported at once (E1), numeric-port rule; lifecycle on `127.0.0.1:0`: health/ready, calculate `0.1+0.2=0.3`, metrics on admin with the five families, pprof on admin when enabled and 404 when not (E4), metrics and pprof 404 on the public listener, admin disabled (E3), bind failure (E2), early return when a listener fails, drain → readyz 503 observed while healthz stays 200 → shutdown, an in-flight request started before the signal completes, a shutdown past the timeout returns an error, healthcheck exit 0/1 incl. a silent server (E5) and an invalid configuration, usage exit 2; end-to-end chain (follow-up (f)): a panicking route returns the 500 problem, the panic log line carries the header's `request_id`, the access line is at error level with status 500 and `http_requests_total{status="500"}` is 1. Whole module: `go vet ./...`, `go test -race ./...` with `-coverpkg=./internal/...` total ≥ 90 % (heavy lease), golangci-lint 0 issues, `go build ./...` without tags. Manual smoke: `go run ./cmd/calculator` on `:4111`/`:4112` answers `add ["0.1","0.2"]` with `0.3` and exits 0 on SIGTERM. Mutation: swap Metrics and Recover in the chain → the end-to-end test fails; remove `Drain()` → the drain test fails.
