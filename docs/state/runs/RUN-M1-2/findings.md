### Findings of UI-CLIENT-01 — typed, never-throwing API client (2026-10-22)
- (a) **UI** [topic: api-contract, reliability-errors] [type: rule] — Rule as built: `createCalculatorApi({ baseUrl, timeoutMs = 8000, fetch? })` posts `{ operands: [...operands] }` to `/api/v1/operations/{operation}` through openapi-fetch with a per-request `fetch` (late-bound `globalThis.fetch` by default) and always an `AbortSignal.timeout`, combined with the caller's signal through `AbortSignal.any`. It never rejects: a response that settles after the combined signal fired → `timeout`/`aborted` (stale bodies never come back as `ok`); 2xx with a `CalculationResult` for the requested operation whose operands and result are contract Decimals (pattern, ≤ 128 characters) → `ok` with an object rebuilt from the four contract fields only; any other 2xx (wrong shape, other operation, non-Decimal, empty, 204) → `unexpected(status)`; non-2xx whose body passes `isProblem` and whose `status` equals the HTTP status → `problem(status, code, title, detail, requestId)`; any other non-2xx → `unexpected(status)`; a thrown error while the combined signal is aborted → `timeout` when the timeout fired first, else `aborted`; an unparsable 2xx body (an object named `SyntaxError`, checked without `instanceof`) → `unexpected(status)`; anything else → `network`. `isProblem` requires string `type`, `title`, `detail`, `requestId`, an integer `status` 400–599, a `code` in `PROBLEM_CODES`, and checks `instance` and `errors` when present. `PROBLEM_CODES` is checked against the contract enum in both directions at compile time. `resolveBaseUrl(configured, origin)` returns the origin for an unset or empty value.
- (b) **UI** [topic: api-contract, ui-accessibility] [type: debt] [target: UI-MODEL-01] — The contract types `requestId` as a string without a minimum length, so a problem with `requestId: ""` reaches the model as a problem with an empty reference. RF-UI-08 shows `Ref: <requestId>` «when available»: the model's error copy treats an empty `requestId` as unavailable (no bare `Ref: `) and tests it. `title`, `detail` and `requestId` are copied verbatim, without a length cap or control-character filtering (a `title` with U+202E passes the guard): the UI never shows `title`/`detail` (RF-UI-08) and renders `requestId` only as a React text node, never as HTML.
- (c) **UI** [topic: api-contract] [type: debt] [target: UI-SCREEN-01] — The client is created once by the real `main.tsx`: `createCalculatorApi({ baseUrl: resolveBaseUrl(import.meta.env.VITE_API_BASE_URL, window.location.origin) })`, provided through `CalculatorApiProvider` around the app (RF-UI-09 «created once and injected through React context»); `useCalculatorApi` throws outside the provider.
- (d) **UI** [topic: security-privacy, api-contract] [type: note] — Security and edge-case review (step 10, independent subagent): no P0–P2. Applied: results rebuilt from the contract fields with Decimal checks (a `__proto__` own key in a 2xx body no longer reaches the caller) and stale bodies reported as aborted/timeout. Recorded, not changed: `resolveBaseUrl` trusts the build-time `VITE_API_BASE_URL` as given (a query or fragment in it would produce a wrong URL; it is operator configuration, and the same-origin default needs none); the production build emits source maps with `sourcesContent` (`build.sourcemap: true`; no secrets, absolute paths or environment values in them — whether the edge serves `.map` files is the edge configuration's choice); `operation` path values are percent-encoded by openapi-fetch; requests carry no credentials beyond same-origin defaults; `pnpm audit --prod` reported no known vulnerabilities (2026-10-22).
