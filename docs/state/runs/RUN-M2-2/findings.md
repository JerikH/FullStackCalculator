- (a) **OPS** [topic: ci-supply-chain, testing-environment] [type: rule] — Rule as built: `.github/workflows/ci.yml.disabled` has the six jobs `contract`, `backend`, `frontend`, `e2e` (needs the first three), `images` and `publish` (needs all five); every step calls `scripts/ci/t3.sh --job <name> [--stage <stage>]` (`t3.sh --list` prints the stages; without `--stage` a job runs its default stages; without `--job` only `contract backend frontend images` run, `e2e` and `publish` only by name; stages marked `+` such as `images/edge-mutations` run only when named). `scripts/ci/check-workflow.py` (30 rules, run by `contract/workflows` on every pull request) pins the structure: exactly the six jobs, `publish.needs`, top-level `contents: read` and `packages: write` only in `publish`, no `pull_request_target`, every `uses:` a 40-hex SHA with a version comment, `persist-credentials: false`, no `${{` in any `run:`, retention and unique names of every upload, the exact `publish.if`, `secrets.GITHUB_TOKEN` only in the step running `--stage push`, no `continue-on-error`, `frontend/.node-version` equal to the Node tag of both Dockerfiles, every `t3.sh` job/stage named by the workflow declared by `t3.sh --list`, every artifact path produced by the Makefile or a script, every `scripts/` path and Make target that `lib.sh` and `t3.sh` call, and the exact Dependabot set (gomod `/backend`, npm `/frontend`, docker `/`, `/backend`, `/frontend`, github-actions `/`; weekly; a `minor-and-patch` group per entry, majors ungrouped).
