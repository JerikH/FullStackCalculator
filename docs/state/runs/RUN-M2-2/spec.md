## 2. Design decisions

**D1. One entry point per job, one stage per workflow step.** Every job calls `scripts/ci/t3.sh --job <name> [--stage <stage>]…`. Without `--stage` a job runs all its default stages in order (that is what a developer or the hosted run gets); the workflow runs **one step per stage** (so artifacts, summaries and failures are visible per piece), and the local proof runs one stage per command (U22). Valid jobs: `contract backend frontend e2e images publish`. With neither `--job` nor `--stage`, `t3.sh` runs the jobs `contract backend frontend images` in full (as today); `e2e` and `publish` run only by name, and `publish` refuses to push outside GitHub Actions (D5). An unknown job or stage exits 2 listing the valid ones. The default T2/T0 paths keep their behavior (the diff-selected `ci_stage_*` functions stay; new T3-only stage functions are added beside them, no logic is duplicated into YAML).

**D2. Tool and runtime pins come from one place each.** Node: `actions/setup-node` with `node-version-file: frontend/.node-version` (new file, one line `24.22.1`, **FU**, U37). pnpm: a new `scripts/ci/setup-pnpm.sh` runs `corepack enable pnpm` and `corepack install --global "$(node -p "require('./frontend/package.json').packageManager")"`, so the integrity-hashed value of `frontend/package.json` is the only source (**FU** OPS-CI-01 (f)); the workflow has no Node or pnpm literal. Go: `actions/setup-go` with `go-version-file: backend/go.mod`, `GOTOOLCHAIN=local` in the backend job so an insufficient toolchain fails instead of downloading another. The structural check asserts that `frontend/.node-version` equals the Node tag of `frontend/Dockerfile` and of the root `Dockerfile` (RNF-OPS-01) and that the workflow contains no `node-version:` literal. Trivy joins `tools/versions.env` (`TRIVY_VERSION=0.76.1`, four SHA-256 values copied from the release's `trivy_0.76.1_checksums.txt`; the Linux amd64 value equals the digest GitHub reports for the asset) and `install-tools.sh`.

**D3. Workflow security (RNF-SEC-06).** Workflow-level `permissions: contents: read`; only `publish` adds `packages: write` (its job-level block restates `contents: read`, because a job-level block replaces the workflow-level one). Triggers `pull_request`, push to `main`, tags `v*`, `workflow_dispatch`; never `pull_request_target`; no secrets are referenced anywhere (PRs, including from forks, run with a read-only token and no credential); `actions/checkout` always with `persist-credentials: false`. Every `uses:` is a 40-character commit SHA with the version in a trailing comment (checked against the tag by `git ls-remote`, annotated tags dereferenced). Event-derived values (`github.ref`, `github.ref_name`, `github.sha`, `github.repository_owner`) reach scripts only through `env:` and are quoted there; no `${{ }}` inside a `run:` body (the structural check rejects any `${{` inside a `run:`). Concurrency: group per workflow and PR number or ref; `cancel-in-progress` only for pull requests, so a push to `main` or a tag is never cancelled while it publishes (RF-OPS-11 «cancels superseded runs» holds for the runs that can be superseded). Each job has a finite `timeout-minutes`. Job setup (each job installs only what its stages need): `contract` = setup-node from `frontend/.node-version`, `scripts/ci/setup-pnpm.sh`, `pnpm -C frontend install --frozen-lockfile`, apt `python3-yaml`, `install-tools.sh actionlint shellcheck`; `backend` = setup-go (`go-version-file: backend/go.mod`, `cache-dependency-path: backend/go.sum`), `GOTOOLCHAIN=local`, `install-tools.sh golangci-lint govulncheck`; `frontend` = setup-node, setup-pnpm, frozen install; `e2e` = the frontend setup plus `pnpm -C frontend exec playwright install --with-deps chromium` (the browser version comes from the lockfile); `images` = apt `python3-yaml python3-jsonschema`, `install-tools.sh hadolint trivy`, checkout with `fetch-depth: 0`; `publish` = checkout with `fetch-depth: 0`, download of the archives. Third-party actions are limited to `actions/{checkout,setup-node,setup-go,upload-artifact,download-artifact}`; image builds, Trivy, GHCR login/push are scripts using the Docker CLI and the pinned binary, so no further third-party action is trusted with the registry token.

**D4. `images` job (RF-OPS-11, RNF-SEC-05).** Builds the three images with the Makefile's variables (`ci_compose_env`: `VERSION`, `COMMIT`, `IMAGE_TAG`): `docker compose build api web` is two pieces `build-api`/`build-web`; `build-aio` is `make image-aio`. Smoke checks: `scripts/ci/image-smoke.sh <api-image> <version> <commit> <port>` (14 checks, hardened run, `docker run -P` publishes only 8081, layer sum under 20 MB — U31); `scripts/ci/edge-smoke.sh <web-image> <api-image>` (real-service suite: the web image in front of the hardened API image on a private network, API also published on `127.0.0.1:<WEB_PORT+1>` for the direct-vs-edge comparisons); `scripts/ci/edge-stub-smoke.sh <web-image>` (599 checks against `stub-upstream.mjs` on a private network); `make smoke-aio`. `export` writes `coverage/images/{calculator-api,calculator-web,calculator}.tar.gz` (`docker save | gzip`) and `coverage/images/image-ids.txt` (repository, tag, image ID, source commit, version). `scan-<image>` runs the pinned Trivy **once** on the exported archive: `trivy image --input <archive> --scanners vuln --format json --exit-code 0` writes `coverage/images/trivy-<image>.json` with every severity and the unfixed findings; the gate is derived from that JSON with `trivy convert --format table --severity HIGH,CRITICAL --ignore-unfixed --exit-code 1` (table in `trivy-<image>-gate.txt` and in the job summary), and an informational table that keeps unfixed HIGH/CRITICAL findings visible is written to `trivy-<image>-all.txt` (not a gate, said so in its header line and in the summary). One database load, one source of truth. The database download is retried up to three times (a database or scanner failure still fails the step), with `--skip-version-check` and `TRIVY_DB_REPOSITORY=ghcr.io/aquasecurity/trivy-db:2,public.ecr.aws/aquasecurity/trivy-db:2` as the fallback list for registry rate limits; no ignore file. If Trivy refuses a gzip archive, `export` keeps a plain `docker save` tar for the scan and gzips only the uploaded copy (decided by the one local scan). Containers and networks are named from `COMPOSE_PROJECT_NAME` (or from the image tag derived from it, as `image-smoke.sh` does) so two sessions never collide, and are removed by name. `VERSION` and `COMMIT` are computed once by `ci_compose_env` and exported to every build; under GitHub Actions a `-dirty` version fails the build stage. `edge-mutations` (the stub suite's 17 rule mutations, minutes each) is a script stage selected by name only — it stays out of the default order and the workflow (hours of hosted time); its subsets are the local proof of the promotion.

**D5. `publish` job (RF-OPS-12).** `needs: [contract, backend, frontend, e2e, images]`; `if: github.event_name == 'push' && !github.event.repository.fork && (github.ref == 'refs/heads/main' || startsWith(github.ref, 'refs/tags/v'))` (pull requests and `workflow_dispatch` never publish; the prefix test is only the cheap filter, the validation is the function). Steps: checkout with `fetch-depth: 0` (ancestry), `download-artifact` of the three image archives, `t3.sh --job publish --stage tags` which calls `scripts/ci/publish-tags.sh publish_tags` with `EVENT`, `REF`, `SHA` from `env:`: `refs/heads/main` → `sha-<40-hex SHA>` and `main`; `refs/tags/vX.Y.Z` where X, Y, Z are `0|[1-9][0-9]*` (no `v1.2`, no `v1.2.3-rc1`, no leading zeros, no build metadata) **and** the tagged commit equal to `SHA` **and** an ancestor of `origin/main` (`git merge-base --is-ancestor`) → `sha-<SHA>` and `X.Y.Z` (the version without `v`; no `main` tag on a release); anything else, an empty ref, a SHA that is not 40 lower-case hex, a missing `origin/main`: exit 1 with the reason, nothing is pushed. `t3.sh --job publish --stage push` recomputes the tags itself from the same three inputs with the same function (nothing computed by `tags` is trusted or passed through an output or file) and refuses to run unless `GITHUB_ACTIONS=true` and the token is set; then it `docker load`s the three archives, verifies each loaded image ID equals `image-ids.txt` (the exact image the `images` job built, smoke-tested, scanned and exported; the `e2e` job tests a composed build of the same commit, not those bits), `docker login ghcr.io` with `GITHUB_TOKEN` on stdin (job-scoped `env:`; the only step that sees it), tag and push each of the three images as `ghcr.io/<lowercased owner>/<image>:<tag>` for every tag, append the pushed digests to the job summary. Image names: `calculator-api`, `calculator-web`, `calculator`. The `tags` stage also runs in the `contract` job on tag events (`if: github.ref_type == 'tag'`, checkout with full history) so a malformed or unreachable tag fails in seconds, not after the whole pipeline. Known and recorded for the closure: a tag push rebuilds the commit with `VERSION=vX.Y.Z` while the earlier `main` push built it with the short SHA, so `sha-<SHA>` is repointed to the release-labelled build of the same commit (the images differ only in the injected version); tag protection or an environment rule is an owner step of G1 (the gating lives in the workflow file that the tag itself carries); the first push of a package may leave it unlinked to the repository because the Dockerfiles carry no `org.opencontainers.image.source` label (read-only here, finding).

**D6. Evidence paths and retention.** Every `upload-artifact` uses a unique name per job/image, `retention-days` (14 for reports and logs, 7 for image archives), `if: ${{ !cancelled() }}` and `if-no-files-found: warn`; a missing expected report is a failure of the **producing** stage (stage functions assert the files, D1), never turned into success by the upload. Artifacts: `api-reference` (`docs/api/index.html`), `coverage-backend` (`coverage/backend/`), `benchmark` (`coverage/bench/`), `fuzz-crashers` (`backend/internal/calc/testdata/fuzz/`, only meaningful on failure), `coverage-frontend` (`coverage/frontend/`), `playwright` (`coverage/e2e/`), `images-calculator-api|-web|(none)` (the three archives, `compression-level: 0` because they are already gzip), `images-manifest` (`coverage/images/image-ids.txt`, downloaded by `publish` with the archives through the pattern `images-*`), `image-reports` (`coverage/images/trivy-*`), all paths produced by the Makefile or the stage functions; the structural check asserts every uploaded path string occurs in the Makefile, `scripts/ci/*.sh`, `scripts/*.sh` or the Playwright config, with one allow-listed exception: `backend/internal/calc/testdata/fuzz`, written by `go test -fuzz` itself when it finds a crasher (uploaded only on failure, `if-no-files-found: ignore`).
