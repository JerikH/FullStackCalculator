## CALC-CORE-01 — Go module, lint configuration, decimal parsing and formatting

**Scope:** RF-CALC-02 (constants), RF-CALC-03, RF-CALC-04, RNF-QUAL-02 (backend lint configuration); registered follow-up from OPS-CI-01 («Findings of OPS-CI-01» (d)): `.golangci.yml` enables gofumpt and goimports, and `scripts/ci/t0.sh` runs on the change (first real backend stage, `./...`).

**Decisions:**
- `go.mod`: module `github.com/JerikH/FullStackCalculator/backend`, `go 1.27.3` (the installed release), no `toolchain` line; requires `github.com/cockroachdb/apd/v3` and `github.com/google/go-cmp` at their latest releases (go-cmp is used by the CALC-OPS-01 and API-HTTPX-01 tests).
- `.golangci.yml` (golangci-lint v2 format): `default: standard` plus bodyclose, contextcheck, copyloopvar, errorlint, gocritic, gosec, intrange, misspell, nilerr, noctx, perfsprint, prealloc, revive (exported, package-comments, var-naming, receiver-naming, indent-error-flow, unused-parameter), thelper, tparallel, unconvert, unparam, usestdlibvars; exclusion presets `std-error-handling`, `common-false-positives`; gosec and perfsprint excluded only in `_test.go`; formatters gofumpt and goimports with `local-prefixes: [github.com/JerikH/FullStackCalculator/backend]`. A linter or setting that golangci-lint 2.15.0 rejects is fixed to the 2.15 name, never dropped silently.
- Constants `Precision = 34`, `MaxExponent = 6144`, `MinExponent = -6143`, `MaxOperandLength = 128`.
- Sentinels whose `.Error()` is the RF-CALC-03 reason, verbatim: `ErrOperandTooLong` `must be at most 128 characters`; `ErrInvalidNumber` `must be a decimal number in JSON number syntax, e.g. "-12.5" or "1e-3"`; `ErrTooManyDigits` `must have at most 34 significant digits`; `ErrOutOfRange` `magnitude is outside the supported range (1e-6143 … 1e6144)` (U+2026).
- `Parse(s)` applies the four rules in RF-CALC-03 order: length in characters (`utf8.RuneCountInString`, as the contract's `maxLength` counts code points: a 100-character non-ASCII string gets the syntax reason, not the length reason), the decimal-string regex, ≤ 34 significant digits after removing trailing zeros, adjusted exponent in [−6143, 6144] for non-zero values.
- **Zero operands are normalised** to a zero with exponent 0 that keeps its sign. Reason: rule 4 exempts zeros, so `0e99999` and `0e9999999999` are valid (the latter overflows apd's int32 exponent at parse time, which for a non-zero value is the «exponent parse overflow» of rule 4 but for a zero must not be); a zero with a huge stored exponent would otherwise reach `Pow`/`Sqrt`/`Mul` and produce clamped or slow intermediate values. The value is unchanged (`Cmp == 0`); the API echoes the operand strings, never the parsed value.
- `Format(d)` per RF-CALC-04: zero (and −0) → `"0"`; reduce; plain for adjusted exponents in [−6, 20]; otherwise lowercase scientific with an explicit exponent sign.
- `FuzzParse`: every accepted operand survives `Format → Parse` with the same value, and `Format` output always matches the decimal-string regex. Crashers are kept under `testdata/fuzz/FuzzParse/`.

**Verification:** `go test -race ./internal/calc/` (valid table incl. 34 digits, trailing zeros, both range ends, `0e99999`, `0e9999999999`, `-0e9999999999`; invalid table for each reason, each rule boundary — 128/129 characters, 34/35 digits, `1e6144`/`1e6145`, `1e-6143`/`1e-6144`, exponent overflow — a 100-character non-ASCII string gets `ErrInvalidNumber` (characters, not bytes), and rule order: a 129-character non-number is `ErrOperandTooLong`, a 35-digit out-of-range number is `ErrTooManyDigits`; format table of RF-CALC-04 incl. the [−6, 20] boundaries `1e-6`/`1e-7`, `1e20`/`1e21`); `FuzzParse` 20 s clean under the `heavy` lease; `bin/golangci-lint run ./...` and `golangci-lint fmt --diff` clean; `go vet ./...`; `go build ./api/` compiles the embedded contract; `scripts/ci/t0.sh --base main` (first real backend stage). Mutation checks: widen the plain-notation upper bound to 21 → the `1e21` row fails; drop the zero exemption of rule 4 → the `0e99999` row fails.

## CALC-OPS-01 — Operation catalog and calculator

**Scope:** RF-CALC-01, RF-CALC-05…RF-CALC-10, RF-CALC-02 (context and trap classification), RNF-PERF-01, RNF-REL-01 (fuzzing).

**Missing:** `backend/internal/calc/{errors.go,operations.go,calculator.go,calculator_test.go,errors_test.go,bench_test.go}`; `FuzzCalculate` in `fuzz_test.go`.

**Decisions:**
- Catalog (RF-CALC-01) in fixed order with the exact symbols (U+2212, U+00D7, U+00F7, U+221A) and descriptions; `Operations()` returns `slices.Clone` (defensive copy); `Has(name)`. `Calculator` is immutable after `New` and safe for concurrent use; each call copies the `apd.Context` value.
- `apd.Context{Precision: 34, MaxExponent: 6144, MinExponent: -6143, Rounding: RoundHalfEven, Traps: DivisionByZero|DivisionUndefined|DivisionImpossible|InvalidOperation|Overflow|SystemOverflow|SystemUnderflow}` (RF-CALC-02); Inexact, Rounded, Underflow, Subnormal, Clamped not trapped.
- `Calculate(ctx, name, operands)`: (1) `ctx.Err()` → returned as is (RF-CALC-10); (2) unknown name → `ErrUnknownOperation` (internal text `unknown operation: "<name>"`, never a detail — API-ROUTES-01 writes its own); (3) arity → `ErrArity` refined with `<op> takes exactly <n> operand(s), got <m>` (singular «operand» for arity 1) (RF-CALC-09); (4) every operand parsed, all failures collected into `*InvalidOperandsError{[]OperandError{Index, Err}}` (RF-CALC-03); (5) apply; (6) classify: pre-check sentinels pass through, DivisionByZero/DivisionUndefined → `ErrDivisionByZero`, Overflow/SystemOverflow/SystemUnderflow → `ErrOverflow`, InvalidOperation/DivisionImpossible → `ErrUndefined`, anything else → a wrapped error that `Outcome` labels `internal`; (7) non-finite result → `ErrOverflow`; (8) `Result{Format(d), cond.Inexact()}`.
- Pre-checks that fix the observable behaviour before apd: divisor zero (incl. 0÷0) → `the divisor must not be zero` (RF-CALC-05); `0^0 = 1`, zero base with negative exponent → `zero cannot be raised to a negative power`, negative base with non-integer exponent → `a negative number raised to a non-integer power is not a real number` (RF-CALC-06); negative non-zero sqrt operand → `square root of a negative number is not a real number`, `√(−0) = 0`, exact roots verified by squaring in a 70-digit context report `inexact: false` (RF-CALC-07); percentage = operand ÷ 100 (RF-CALC-08). Error texts are `.Error()` of the returned error and match the RF strings exactly; `errors.Is` reaches the sentinel.
- Overflow text `the result is outside the supported range (1e-6143 … 1e6144)` (RF-CALC-06); underflow rounds toward 0 and reports inexact (RF-CALC-02, `1e-6000 × 1e-6000 = 0`, inexact).
- **Results below the range flush to zero.** apd keeps subnormal results whose adjusted exponent is below −6143 (`1e-6143 ÷ 10 = 1e-6144` exact, `1e-6143 % = 1e-6145`, `1.234567e-6143 × 1e-30 = 1.235e-6173` inexact). RF-CALC-02 fixes adjusted exponents to [−6143, 6144] and says an underflowing result rounds toward 0 and is reported inexact; such results would also be rejected by operand rule 4 if sent back. Rule: a finite non-zero result with adjusted exponent < −6143 becomes `0` with `inexact: true`. Every result is therefore a valid operand.
- The power pre-check for a negative base applies to a negative **non-zero** base (`power -0 0.5 = 0`; `power -0 -1` is the zero-base DIVISION_BY_ZERO, which also prevents apd's `-Infinity` without a condition).
- **Power out of range decided from the operands** (measured on apd v3.2.3, scratch probe): for exponents too large for apd's working exponent, `Context.Pow` returns the error `exponent out of range` with unreliable flags — `2^1e30` Overflow, `2^-1e30` Underflow|Inexact|Subnormal|Rounded, `0.1^1e30` Underflow only, and `0.1^-1e30` (= 10^1e30) Underflow only. Classifying by the flags would label `0.1^1e30` `internal` and `0.1^-1e30` wrong. Rule: when `Pow` fails with an overflow/underflow condition, |base| > 1 with a positive exponent or |base| < 1 with a negative one → `ErrOverflow`; the other two quadrants → result 0, inexact (RF-CALC-02). |base| = 1 never fails (`1^1e30 = 1`, `(−1)^1e30 = 1`).
- **Exact fractional powers report `inexact: false`** (RF-CALC-09 «exactly when the result was rounded»): apd reports Inexact for `4^0.5 = 2`, `16^0.25 = 2`, `1^0.5 = 1`. When the exponent is not an integer and apd reports Inexact, write the reduced exponent as p/q in lowest terms; if q ≤ 64 and |p| ≤ 64, verify `r^q = base^p` (or `r^q · base^|p| = 1` for p < 0) exactly in a context wide enough for both products; when it holds, clear Inexact and Rounded. Outside the bound (e.g. `8^0.3333333333333333333333333333333333`, whose exponent is not 1/3, correctly inexact) apd's flag stands. Residual: an exact result whose exponent has a denominator above 64 is still reported inexact — recorded as a finding.
- **Measured cost outside the six benchmark cases:** fractional powers at the range edges take about 3 ms (`(9.99…e6144)^0.5` 2.7 ms, `(1e-6143)^0.5` 3.2 ms on this machine, unoptimised probe), still bounded; the spec review measured up to 14.1 ms for `(9.99…e6144)^0.99…9`. The six named cases are RNF-PERF-01's measure and stay as named (`power_fractional` = `2^0.5`); the worst cases are measured into `evidence/` and recorded as a finding against the «no per-request timeout» rationale.
- `Outcome(err)` → `ok`, `unknown_operation`, `invalid_input` (arity and invalid operands), `division_by_zero`, `undefined_result`, `overflow`, `canceled` (Canceled and DeadlineExceeded), `internal` (RF-CALC-10).
- Expectation tables are never edited to match apd; a mismatch is fixed in `classify` or a pre-check.
- `FuzzCalculate`: no input yields `Outcome == "internal"`; every result matches the decimal-string regex; add and multiply are commutative. `BenchmarkCalculate`: the six RNF-PERF-01 cases.

**Verification:** `go test -race -cover ./internal/calc/` ≥ 95 % (heavy lease for the coverage run); the result and error tables of RF-CALC-05…09 exactly, including `divide 1 3`, `divide 2 3` (half-even), `sqrt 2`, `power 2 1e30` and `multiply 1e6144 10` → overflow; `FuzzCalculate` 30 s clean; every benchmark case < 1,000,000 ns/op, output recorded in `evidence/`. Mutation checks: remove the `0^0` pre-check → its test fails (named in the task); make `Operations()` return the internal slice → the defensive-copy test fails; make the squaring helper always answer «exact» → `sqrt 2` turns exact and its row fails (apd never flags an exact root inexact, so removing the check alone is not observable); flush below the range removed → the `1e-6143 %` row fails.

**Files:** `backend/internal/calc/errors.go`, `operations.go`, `calculator.go`, `calculator_test.go`, `errors_test.go`, `bench_test.go`, `fuzz_test.go` (add `FuzzCalculate`), `testdata/fuzz/FuzzCalculate/**` (only if a crasher is found), `backend/go.mod`/`go.sum` (go-cmp becomes a direct requirement).

## API-HTTPX-01 — HTTP platform: problems, decoding, request context, middleware

**Scope:** RF-API-05 (problem catalog, `Codes()`), RF-API-06 (`Methods`, `NotFound`), RF-API-07 (request ID, `RequestInfo`, route tagging), RF-API-11 (`Recover`), RF-API-04 rules 2–4 (`DecodeJSON`), RF-API-08 (`SecureHeaders`, `no-store` on JSON and problem responses), the access-log middleware of RF-OBS-05, RNF-SEC-01, RNF-SEC-02. Package `backend/internal/platform/httpx`.

**Missing:** everything — `doc.go`, `problem.go`, `respond.go`, `decode.go`, `requestinfo.go`, `middleware.go`, `methods.go` and their tests.

**Interface produced** (consumed later by API-ROUTES-01, OBS-METRICS-01, OBS-RUNTIME-01): `Code` and the 11 constants; `Codes() []Code` (sorted); `FieldViolation{Field, Reason}`; `Problem{Type, Title, Status, Detail, Instance, Code, RequestID, Errors}`; `NewProblem(code, detail, violations...)`; `WriteProblem(w, r, p)`; `WriteJSON(w, r, status, v)` (takes the request so its encoding fallback is a complete problem); `MaxBodyBytes = 4096`; `DecodeJSON(w, r, dst) *Problem`; `HeaderRequestID`; `RequestInfo{ID, Route, Status, Bytes}` + `StatusOrOK()`; `Info(ctx)`; `RequestID(ctx)`; `RequestContext`; `Route(pattern, h)`; `Middleware`; `Chain(h, mws...)` (mws[0] outermost); `AccessLog(logger)`; `Recover(logger)`; `SecureHeaders`; `Methods` (map method → handler, implements `http.Handler`); `NotFound`.

**Decisions:**
- **Codes.** `Codes()` returns the 11 codes the service emits: the contract enum minus `RATE_LIMITED` and `SERVICE_UNAVAILABLE`, which are edge-only (RF-API-05). RF-API-09 asserts the service set ⊆ the contract enum; the subset is strict by design. Status and title per RF-API-05; `type = urn:calculator:problem:<kebab-case code>`. An unknown code degrades to `INTERNAL_ERROR` (a programming error never emits an undocumented code).
- **Problem JSON.** `detail` and `requestId` are always serialised (no `omitempty`) because the contract requires them; `instance` and `errors` are `omitempty` (`instance` is always set by `WriteProblem`; `errors` only for `VALIDATION_FAILED`, which is the caller's responsibility — API-ROUTES-01). `WriteProblem` sets `instance = r.URL.Path` and `requestId = RequestID(r.Context())`, so `requestId` equals the `X-Request-ID` header (RF-API-07).
- **Writing.** Marshal before touching headers; `Content-Type` `application/json; charset=utf-8` or `application/problem+json`, `Cache-Control: no-store` and `Content-Length` on every JSON and problem body (RF-API-08). If a `WriteJSON` value cannot be encoded (a programming error), the response is `WriteProblem(w, r, NewProblem(CodeInternal, "an unexpected error occurred"))` — `instance` and `requestId` included, as the contract describes for every service problem. A failed body write is ignored (the client went away).
- **Decoding (RF-API-04 rules 2–4).** Order: (2) media type parsed with `mime.ParseMediaType`, must be `application/json` (parameters allowed, case-insensitive) → 415 `Content-Type must be application/json`; (3) the whole body is read first with `io.ReadAll(http.MaxBytesReader(w, r.Body, 4096))` → 413 `request body must not exceed 4096 bytes` for any body over the limit, whatever its content (a streaming decoder would report a syntax error in an oversize body before reaching the limit); (4) the bytes are parsed: 400 `MALFORMED_REQUEST` with exactly the four details of RF-API-04 — empty or whitespace-only → `request body must not be empty`; syntax error or truncated JSON (and a body read error) → `request body is not valid JSON`; unknown field → `unknown field "<name>"` (the name quoted with `%q` — the one allowed reflection of RNF-SEC-02, bounded by the 4 KiB body); trailing data after the first value, a top-level value that is not an object (array, string, number, boolean, **`null`**) and a field of the wrong JSON type → `request body must contain a single JSON object`.
  Steps: first value into a `json.RawMessage`; a second `Decode` must return `io.EOF`; the raw value's first byte must be `{`; **top-level keys are matched exactly**: the object's top-level keys are read with `Decoder.Token` and each must be byte-equal to a JSON name of `dst`'s struct fields (tag name, or the Go field name without a tag; `-` skipped) — otherwise `unknown field %q` — because `encoding/json` matches keys case-insensitively (`{"OPERANDS":["9"]}` decodes into `operands`, measured), while the contract's `CalculationRequest` has `additionalProperties: false`; finally a strict decode (`DisallowUnknownFields`) into `dst`. The exact-key check applies when `dst` points to a struct; nested objects are decoded by the standard rules (the API's request is flat: `operands` is raw). Rationale for the rest: `null` would otherwise decode silently into a zero `dst`; a type-mismatch detail must not name the field because `UnmarshalTypeError.Field` contains map keys from the input (RNF-SEC-02); RF-API-04 fixes the MALFORMED details to those four strings. Repeated keys: the last occurrence wins (standard decoder behaviour, pinned by a test with a `json.RawMessage` `operands` field); a repeated key in another case is an unknown field. Rule 1 (unknown operation before the body) and rules 5–8 belong to API-ROUTES-01, whose `operands` field is raw, so rules 5–6 never reach the type-mismatch path.
- **Request ID (RF-API-07).** Inbound `X-Request-ID` matching `^[A-Za-z0-9._-]{1,128}$` is propagated; otherwise (absent, empty, invalid characters, 129+ characters) it is replaced by `crypto/rand.Text()`. The response header is set before the handler runs. `RequestInfo` starts with `Route: "unmatched"`; `Route(pattern, h)` records the pattern (never the raw path). The response recorder records the first final status (1xx informational statuses are passed through but not recorded; an implicit 200 on the first `Write`) and the bytes written, and exposes `Unwrap()` for `http.ResponseController`.
- **Access log (RF-OBS-05).** One `http request` line per request — written in a `defer`, so a request aborted with `http.ErrAbortHandler` is still logged — at `info`, `error` for status ≥ 500, with `method`, `route`, `path`, `status`, `bytes`, `duration_ms`, `remote_addr`, `user_agent`; logged with the request context so the request-aware logger of OBS-METRICS-01 adds `request_id`.
- **Recover (RF-API-11).** A panic becomes 500 `INTERNAL_ERROR` `an unexpected error occurred`, the panic value never reaches the client; it is logged at error level (`panic recovered`, with the panic value and the stack) with the request context. `http.ErrAbortHandler` is re-panicked. If the handler already wrote a status, nothing more is written to the client, but the recorded status becomes 500 so the access log and the metrics count the panic as a 500 (RF-API-12). Recover sits inside AccessLog (RF-API-12 order, composed by OBS-RUNTIME-01), so the access line reports 500.
- **SecureHeaders (RF-API-08).** `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Cross-Origin-Resource-Policy: same-origin`, set before the handler (the embedded web handler of OPS-IMAGE-01 replaces the CSP for app files).
- **Methods (RF-API-06).** A known path with a wrong method → 405 with `Allow` = the registered methods sorted and joined by `, ` and detail `<METHOD> is not allowed; use <allowed>`; the method is the only reflected token, bounded by the HTTP token grammar and JSON-encoded (RNF-SEC-02). `NotFound` → 404 `no route matches the request method and path` (fixed, no input reflected). `HEAD` is a method like any other: it is served only where registered, otherwise 405 (the contract declares no `HEAD` operation).

**Verification:** `go test -race -cover ./internal/platform/httpx/` ≥ 90 % (heavy lease for the coverage run): the problem catalog table (status, title, type URN for all 11; `Codes()` sorted and equal to the 11; unknown code → internal); `WriteProblem` headers and body (`instance`, `requestId` = header, `errors`, `detail` present even when empty); `WriteJSON` headers/body and the unencodable fallback (500, problem media type, `detail`, `requestId`); the decoding table: ok, charset parameter, uppercase media type, trailing whitespace, wrong/missing media type, empty, whitespace-only, syntax, truncated, unknown field, hostile unknown field name (quotes, `<`, a backslash) appearing only `%q`-quoted in the detail, two objects, trailing garbage, oversize invalid JSON → 413, oversize trailing garbage → 413, `OPERANDS` and a mixed-case duplicate key → `unknown field`, array, `null`, string, wrong field type with a map key (detail does not contain the key), exactly 4096 bytes accepted, 4097 bytes → 413, excess after a valid first object → 413, repeated `operands` key → last occurrence; request ID valid/invalid table incl. 128 vs 129 characters; route and status recording, implicit 200, bytes; access-log fields and the error level for 5xx; panic → problem, no leak, logged with the request id (test logger that adds `request_id` from the context), access line status 500; `ErrAbortHandler` re-panic; panic after a written status writes nothing more; chain order; secure headers; `Methods` dispatch, 405 + `Allow` + detail; `NotFound`. Mutation check (named in the task): drop the `^` anchor of the request-ID regex → the invalid-ID test fails; plus: remove the `{` first-byte check → the `null` row fails. `bin/golangci-lint run ./...`, `go vet ./...`.

**Files:** `backend/internal/platform/httpx/doc.go`, `problem.go`, `respond.go`, `decode.go`, `requestinfo.go`, `middleware.go`, `methods.go`, `problem_test.go`, `respond_test.go`, `decode_test.go`, `requestinfo_test.go`, `middleware_test.go`, `methods_test.go`.
