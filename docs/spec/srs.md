# Software Requirements Specification — FullStackCalculator

**Version:** 1.0 · **Date:** 2026-10-22

## 1. Introduction

### 1.1 Purpose
FullStackCalculator is a full-stack calculator: a React + TypeScript single-page app that delegates **all** arithmetic to a Go REST microservice computing with arbitrary-precision decimals (34 significant digits). It is built to production standards: a contract-first API, layered and testable code, observability, hardened containers, CI definitions and documentation. This document fixes the observable behavior every task implements and verifies.

### 1.2 Scope
In scope for version 1: the seven operations (add, subtract, multiply, divide, power, square root, percentage); the REST API with RFC 9457 errors and its OpenAPI 3.1 contract; the Go service with logs, metrics and drain-aware probes; the web app (keypad, keyboard, history, themes, accessibility); two delivery topologies (split nginx + API containers, and one all-in-one container); local test tiers; CI and Dependabot definitions; README, ADRs and verification records.

Out of scope (design exclusions): CORS (every topology is same-origin), user accounts (history lives in the browser), expression parsing (chaining is sequential), distributed rate limiting (the limit is per edge instance), localisation (English only).

### 1.3 Definitions
| Term | Meaning |
|---|---|
| Decimal string | A JSON string in JSON-number syntax, regex `^-?(0|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?[0-9]+)?$`, at most 128 characters. Every operand and result travels as one. |
| Adjusted exponent | Exponent of the most significant digit: `exponent + digits − 1`, after removing trailing zeros. |
| Inexact | The exact mathematical result could not be represented in 34 significant digits and was rounded (half-even). |
| Problem | An RFC 9457 `application/problem+json` body with the calculator extensions `code`, `requestId` and, for validation failures only, `errors[]`. |
| Edge | The nginx container of the split topology: static app, reverse proxy, browser policy, rate limit. |
| Admin listener | The service's private second listener (`:9091` by default) serving metrics and optional pprof; never published. |
| Draining | Shutdown phase in which readiness answers 503 while in-flight requests finish. |

## 2. Overall description

### 2.1 Product perspective
A browser loads the app from the edge (split topology, `http://localhost:8080`) or from the Go binary itself (all-in-one). Every calculation is a `POST /api/v1/operations/{operation}` to the Go service on the same origin. The service has no database and no runtime integrations. Images are built locally; CI definitions publish them to GitHub Container Registry once the owner enables the workflows.

### 2.2 Actors
| Actor | Description | Permissions summary |
|---|---|---|
| Visitor | Anonymous browser user (keypad, keyboard or touch). The only UI role. | Calculate, edit entry, use history, choose theme |
| API client | curl or any system calling the REST API directly. | Every public endpoint; the API is unauthenticated by design |
| Operator | Runs the containers, reads structured logs, scrapes metrics from the admin listener. | Admin listener (metrics, pprof when enabled), probes, configuration |
| Reviewer | Evaluates the repository: reads the README, runs the stack, calls the API, inspects tests, coverage and ADRs. | Read the repository, run the documented commands |
| Developer | A human or agent contributor working in an isolated local environment. | Local tiers, dev servers, images |
| Automation | GitHub Actions CI and Dependabot, once enabled by the owner. | Repository read; `packages: write` only in the publish job |

### 2.3 Assumptions and dependencies
- Local machine: Go ≥ 1.25 (1.27.3 installed), Node 24, pnpm 10, Docker with Compose v2 (`--wait`), Playwright Chromium.
- Libraries: `cockroachdb/apd/v3`, `log/slog`, `prometheus/client_golang`; tests: `google/go-cmp`, `pb33f/libopenapi` + `libopenapi-validator`, `go.yaml.in/yaml/v3`. Frontend: React 19, TypeScript ≥ 5.9 strict, Vite ≥ 7, `openapi-fetch`, `openapi-typescript`, Vitest, RTL, user-event, MSW 2, vitest-axe, Playwright, `@axe-core/playwright`.
- The latest stable release of each library at implementation time; lockfiles committed.

### 2.4 General constraints
- Go module path `github.com/JerikH/FullStackCalculator/backend`, used in `go.mod`, every import, `.golangci.yml` `goimports.local-prefixes` and the buildinfo `-X` ldflags.
- Image names `calculator-api`, `calculator-web`, `calculator`; GHCR references lowercase `ghcr.io/jerikh/fullstackcalculator/<image>`; linux/amd64.
- Docker base images pinned by tag, GitHub Actions by full commit SHA, standalone tools in `tools/versions.env`.
- No paid services. Local only: no public hosting. The owner creates the remote, pushes and enables workflows.
- UI copy, API messages and documentation in English; exact strings are fixed below and asserted by tests.

## 4. Functional requirements

Priority: **Must** unless stated. Exact strings are normative and tests assert them.

### 4.1 CALC — Calculation engine

| ID | Requirement | Priority | Use case(s) |
|---|---|---|---|
| RF-CALC-01 | The engine shall expose exactly seven operations, in this fixed catalog order (name / symbol / arity / description): `add` `+` 2 `Sum of two numbers`; `subtract` `−` (U+2212) 2 `Difference of two numbers`; `multiply` `×` 2 `Product of two numbers`; `divide` `÷` 2 `Quotient of two numbers`; `power` `^` 2 `First number raised to the power of the second`; `sqrt` `√` 1 `Principal square root`; `percentage` `%` 1 `Value divided by one hundred`. The catalog is returned as a defensive copy. | Must | UC-API-01 |
| RF-CALC-02 | Arithmetic shall use precision 34, half-even rounding and adjusted exponents in [−6143, 6144]. Trapped: DivisionByZero, DivisionUndefined, DivisionImpossible, InvalidOperation, Overflow, SystemOverflow, SystemUnderflow. Not trapped: Inexact, Rounded, Underflow, Subnormal, Clamped (an underflowing result rounds toward 0 and is reported inexact). | Must | UC-API-02 |
| RF-CALC-03 | Operand validation shall apply, in order: length ≤ 128 (`must be at most 128 characters`); decimal-string syntax (`must be a decimal number in JSON number syntax, e.g. "-12.5" or "1e-3"`); ≤ 34 significant digits after removing trailing zeros (`must have at most 34 significant digits`); for non-zero values an adjusted exponent in [−6143, 6144], exponent parse overflow included (`magnitude is outside the supported range (1e-6143 … 1e6144)`). Every invalid operand is reported with its index, not only the first. | Must | UC-API-02 |
| RF-CALC-04 | Results shall be formatted canonically, mirroring JavaScript `Number#toString`: zero (including −0) → `"0"`; trailing zeros removed; plain notation for adjusted exponents in [−6, 20]; otherwise lowercase scientific with explicit exponent sign (`1e+21`, `1.5e+25`, `1e-7`, `-2.5e-10`). Every formatted result matches the decimal-string syntax. | Must | UC-API-02 |
| RF-CALC-05 | `add`, `subtract`, `multiply` and `divide` shall compute a+b, a−b, a×b and a÷b exactly where representable (`0.1 + 0.2 = 0.3`). A zero divisor, including 0÷0, yields `DIVISION_BY_ZERO` with detail `the divisor must not be zero`. | Must | UC-API-02 |
| RF-CALC-06 | `power` shall compute aᵇ with `0^0 = 1`; zero to a negative power yields `DIVISION_BY_ZERO` (`zero cannot be raised to a negative power`); a negative base with a non-integer exponent yields `UNDEFINED_RESULT` (`a negative number raised to a non-integer power is not a real number`); a result beyond the range yields `OVERFLOW` (`the result is outside the supported range (1e-6143 … 1e6144)`). | Must | UC-API-02 |
| RF-CALC-07 | `sqrt` shall return the principal square root; a negative operand yields `UNDEFINED_RESULT` (`square root of a negative number is not a real number`); `√(−0) = 0`; exact roots report `inexact: false`, verified by squaring the result. | Must | UC-API-02 |
| RF-CALC-08 | `percentage` shall return the operand divided by one hundred, independent of any other operand. | Must | UC-API-02 |
| RF-CALC-09 | The engine shall report `inexact: true` exactly when the result was rounded; a wrong operand count yields an arity error whose message is `<op> takes exactly <n> operand(s), got <m>` (`divide takes exactly 2 operands, got 3`, `sqrt takes exactly 1 operand, got 2`); a non-finite result is treated as `OVERFLOW`. No input produces an unclassified error. | Must | UC-API-02 |
| RF-CALC-10 | A calculation whose context is already cancelled shall return the cancellation error, and every error shall map to one bounded outcome label: `ok`, `unknown_operation`, `invalid_input`, `division_by_zero`, `undefined_result`, `overflow`, `canceled`, `internal`. | Must | UC-API-02 |

### 4.2 API — HTTP API and contract

| ID | Requirement | Priority | Use case(s) |
|---|---|---|---|
| RF-API-01 | The contract shall be an OpenAPI 3.1 document at `backend/api/openapi.yaml` with components `Decimal`, `OperationName`, `CalculationRequest`, `CalculationResult`, `OperationInfo`, `OperationCatalog`, `ProblemCode`, `Problem`, `FieldViolation`, `Health`; it lints clean with Redocly (`recommended` plus `operation-4xx-response`, `no-unused-components`, `info-license-strict` as errors; `security-defined: off`); it is embedded in the binary (`api.Spec`) and served at `GET /api/v1/openapi.yaml` as `application/yaml` with `Cache-Control: no-store`. | Must | UC-API-01 |
| RF-API-02 | `GET /api/v1/operations` shall return `200 {"operations":[{name,symbol,arity,description}…]}` in catalog order. | Must | UC-API-01 |
| RF-API-03 | `POST /api/v1/operations/{operation}` with `{"operands":[…]}` shall return `200 {"operation","operands","result","inexact"}`, echoing the operand strings unchanged (e.g. divide `["1","3"]` → `"0.3333333333333333333333333333333333"`, `inexact: true`). Bodies are camelCase JSON, `application/json; charset=utf-8`. | Must | UC-API-02 |
| RF-API-04 | Requests shall be decoded in this order: (1) operation not in the catalog → 404 `UNKNOWN_OPERATION` (`operation "modulo" is not supported; see GET /api/v1/operations`), checked before the body is read; (2) media type not `application/json` (parameters allowed) → 415 (`Content-Type must be application/json`); (3) body over 4096 bytes → 413 (`request body must not exceed 4096 bytes`); (4) empty, invalid JSON, wrong top-level type, unknown field or trailing data → 400 `MALFORMED_REQUEST` (a repeated key is not an error: the last occurrence wins, as in the standard JSON decoder) (`request body must not be empty`, `request body is not valid JSON`, `unknown field "x"`, `request body must contain a single JSON object`); (5) `operands` missing or null → 400 `VALIDATION_FAILED`, field `operands`, reason `is required`; (6) wrong JSON type → reason `must be an array of decimal strings, e.g. ["2", "3"]`; (7) wrong count → the arity message; (8) invalid operands → one `errors[]` entry per bad operand, field `operands[i]`. Details: rules 5/6 `one or more fields are invalid`, rule 7 the arity message, rule 8 `one or more operands are invalid`. | Must | UC-API-02 |
| RF-API-05 | Every error response of the service (API routes and unmatched routes) shall be a Problem `{type, title, status, detail, instance, code, requestId[, errors]}` with `type = urn:calculator:problem:<kebab-code>`, `instance` = request path, `errors` only for `VALIDATION_FAILED`. Edge-generated problems (RF-OPS-04) carry the same fields except that `instance` may be omitted; the draining readiness 503 is Health JSON (RF-OBS-03), not a Problem. Codes / status / title: `MALFORMED_REQUEST` 400 Malformed request; `VALIDATION_FAILED` 400 Validation failed; `NOT_FOUND` 404 Not found; `UNKNOWN_OPERATION` 404 Unknown operation; `METHOD_NOT_ALLOWED` 405 Method not allowed; `PAYLOAD_TOO_LARGE` 413 Payload too large; `UNSUPPORTED_MEDIA_TYPE` 415 Unsupported media type; `DIVISION_BY_ZERO` 422 Division by zero; `UNDEFINED_RESULT` 422 Undefined result; `OVERFLOW` 422 Result out of range; `RATE_LIMITED` 429 Too many requests (edge only); `SERVICE_UNAVAILABLE` 503 Service unavailable (edge only); `INTERNAL_ERROR` 500 Internal server error. 400 means the request is wrong; 422 means it is well-formed but the mathematics has no representable answer. | Must | UC-API-02 |
| RF-API-06 | An unmatched route shall return 404 `NOT_FOUND` with the fixed detail `no route matches the request method and path`; a known path with a wrong method shall return 405 `METHOD_NOT_ALLOWED` with an `Allow` header and detail `<METHOD> is not allowed; use <allowed>` (e.g. `DELETE is not allowed; use GET, POST`). Every error, including these, is problem+json. | Must | UC-API-02 |
| RF-API-07 | Every response shall carry `X-Request-ID`: an inbound value matching `^[A-Za-z0-9._-]{1,128}$` is propagated, anything else is replaced by a generated one (`crypto/rand.Text()`); a problem's `requestId` equals the header. | Must | UC-API-01, UC-API-02 |
| RF-API-08 | Responses under `/api/*` and the probes shall carry `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`; responses served directly by the service also carry `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'` and `Cross-Origin-Resource-Policy: same-origin` (the embedded web handler replaces the CSP with the browser policy of RNF-SEC-03 for app files). Behind the edge, the edge owns the security headers (RF-OPS-04). | Must | UC-API-01, UC-API-02 |
| RF-API-12 | The service's handler chain shall be composed, outermost first, RequestContext → AccessLog → Metrics → Recover → SecureHeaders → router, so a panic is logged with its request ID and counted as a 500. | Must | UC-API-02 |
| RF-API-09 | Contract tests shall validate every handler response against the embedded contract (`pb33f/libopenapi-validator`), assert the catalog equals the `OperationName` enum in the same order, and assert the service's problem codes are a subset of the `ProblemCode` enum. | Must | — |
| RF-API-10 | TypeScript types shall be generated from the contract with `openapi-typescript` into `frontend/src/shared/api/schema.gen.ts`, committed; regenerating them produces no diff. | Must | — |
| RF-API-11 | A panic or unexpected condition shall return 500 `INTERNAL_ERROR` with detail `an unexpected error occurred`, never leaking internals, and is logged with its `request_id` and stack. | Must | UC-API-02 |

| ID | Requirement | Priority | Use case(s) |
|---|---|---|---|
| RF-OBS-01 | Configuration shall come from environment variables only: `CALC_HTTP_ADDR` (`:8081`, non-empty host:port), `CALC_ADMIN_ADDR` (`:9091`, empty disables the admin listener), `CALC_LOG_LEVEL` (`info`; debug/info/warn/error), `CALC_LOG_FORMAT` (`json`; json/text), `CALC_SHUTDOWN_TIMEOUT` (`15s`, > 0), `CALC_SHUTDOWN_DRAIN` (`0s`, ≥ 0), `CALC_PPROF` (`false`, ParseBool). | RF-OBS-07 | `GET /debug/pprof/*` shall exist on the admin listener only when `CALC_PPROF=true`; metrics and pprof are never served on the public listener. | Must | UC-OBS-01 |
| RF-OBS-08 | `calculator healthcheck` shall probe `http://127.0.0.1:<port>/healthz` with a 2 s timeout and exit 0 when healthy, 1 otherwise (distroless images have no curl). | Must | UC-OBS-01 |
| RF-OBS-09 | Version and commit shall be injected with `-ldflags -X …/internal/buildinfo.Version|Commit`, falling back to the embedded VCS revision, and reported by `/healthz` and `calculator_build_info`. | Must | UC-OBS-01 |

Inputs stay enabled; the state machine ignores them. | Must | UC-UI-01 |
| RF-UI-08 | Errors shall replace the value with exact copy in a `role="alert"` region: `DIVISION_BY_ZERO` `Cannot divide by zero`; `UNDEFINED_RESULT` `Result is undefined`; `OVERFLOW` `Result is out of range`; `VALIDATION_FAILED`/`MALFORMED_REQUEST` `Invalid input`; `RATE_LIMITED` `Too many requests, try again shortly`; `SERVICE_UNAVAILABLE` and network failure `Calculator service is unreachable`; timeout `Calculator service timed out`; anything else `Something went wrong`; plus `Ref: <requestId>` when available. ## 5. Non-functional requirements

| ID | Area | Requirement | Measure |
|---|---|---|---|
| RNF-SEC-01 | Security | Input is bounded at every layer: headers 16 KiB, body 4 KiB (edge transport limit 1 MiB), operand 128 characters / 34 significant digits / exponent range, arity ≤ 2. | Transport tests at each bound; E2E 413 |
| RNF-SEC-02 | Security | No raw client input is reflected in a problem `detail`, edge-built JSON or a metric label, except the operation name quoted with `%q`, the unknown field name in `unknown field "x"` (quoted with `%q`, bounded by the 4 KiB body) and the method in the 405 detail (bounded by the HTTP token grammar); all are JSON-encoded in `application/problem+json` served with `nosniff` and `default-src 'none'`; request IDs, operands and raw paths are never metric labels. | Transport and metrics tests; edge config review |
| RNF-SEC-03 | Security | Browser policy on HTML (edge and embedded handler): `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; font-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `Cross-Origin-Opener-Policy: same-origin`. No inline scripts or styles, nonces, `unsafe-inline` or CORS. No HSTS on the plain-HTTP local topology. | E2E header assertions; zero CSP violations in the browser |
| RNF-SEC-04 | Security | Containers run non-root with a read-only root filesystem, all capabilities dropped and `no-new-privileges`; the admin port is never published. | compose config; image smoke tests |
| RNF-SEC-05 | Security | Supply chain: govulncheck clean, `pnpm audit --prod --audit-level high` clean, Trivy fixable HIGH/CRITICAL = 0. | CI jobs `backend`, `frontend`, `images` |
| RNF-SEC-06 | Security | CI: `contents: read` by default, `packages: write` only in `publish`, actions pinned to full SHAs with the version in a comment, `persist-credentials: false`, no `pull_request_target`, no credentials in PR builds. | actionlint + workflow review |
| RNF-PERF-01 | Performance | Every `BenchmarkCalculate` case (`add`, `divide_repeating`, `sqrt_irrational`, `power_large_integer`, `power_fractional`, `power_overflow`) runs under 1,000,000 ns/op, so no per-request timeout is needed. | `make bench`; numbers in README |
| RNF-QUAL-01 | Quality | Coverage: backend ≥ 90 % of statements across `./internal/...`; frontend ≥ 90 % lines, statements and functions, ≥ 85 % branches. | `make coverage` |
| RNF-QUAL-02 | Quality | Static checks clean: gofumpt/goimports, `go vet`, golangci-lint v2 (repository config), ESLint `strictTypeChecked` + react-hooks + jsx-a11y with zero warnings, Prettier, `tsc --noEmit` strict, Redocly, hadolint, actionlint. No `any`, no non-null `!`, no lint disable without a one-line justification. No check is weakened to pass (thresholds, exclusions, `--passWithNoTests`, `continue-on-error`, blanket ignores, relaxed contract or Redocly rules); expectation tables are never edited to match a library. | `make lint`; review |
| RNF-A11Y-01 | Accessibility | Zero axe violations: vitest-axe on the rendered App; `@axe-core/playwright` on initial and error states in both themes on both browser projects. | Component tests; E2E |
| RNF-REL-01 | Stability | Fuzzing finds no panic or unclassified error; cancelled and stale responses never change the display or history; draining returns 503 readiness before shutdown; generated types and handlers never drift from the contract. | Fuzz, hook, lifecycle and contract tests |
| RNF-OPS-01 | Operations | Reproducible builds: Go ≥ 1.25 and Node 24 floors, committed `go.sum` and `pnpm-lock.yaml`, pnpm via `packageManager`/corepack, base images pinned by tag, standalone tools pinned in `tools/versions.env`, linux/amd64 images. | Builds from a clean clone |
| RNF-OPS-02 | Operations | Local verification stays short: agent sessions run tiers 0 and 1 only (touched packages, `tsc`, lint of touched code, single specs); the composed-stack E2E runs once locally during delivery and that run is recorded; complete suites belong to CI. | `context/test-environment.md` measured durations |
